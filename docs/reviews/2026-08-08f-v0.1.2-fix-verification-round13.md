## 1. §2.13：`information_set`/`internal_state` 从字面量 `{}` 改为真实内容

`agent/handler.py::handle_agent_observe` 此前从不写回 `event["information_set"]`
（enqueue 时传入的字面量 `{}` 原样保留到落盘），`handle_agent_decide` 也从不写回
`event["internal_state"]`。两者都是 KPI-006 追溯链/决策可解释性的关键字段
（event-schema.md §4.4/§4.5），九轮里一直是空壳。

- `handle_agent_observe` 新增调用已存在但此前只在 `handle_agent_decide` 内部使用
  的 `_build_information_set`，把观察到的真实 best_bid/ask/深度/钱包/仓位/保证金率
  等写回 `event["information_set"]`。
- `handle_agent_decide` 按代理类型分别记录 `internal_state`：做市商记录
  `inventory_units`/`margin_ratio_bp`/`valuation_mark_half_ticks`；信念代理记录
  `signal_bp`。两者字段集合刻意不同，用于证明不是共享的通用占位符。
- 这两个字段在摘要哈希中被显式排除（`digest.py`/`event-schema.md` §7 明文），改动
  不影响 KPI-007 可重放性哈希校验。

新增 `tests/unit/agent/test_observe_decide_state.py`（5 用例），故障注入验证有效。

## 2. §2.6：`endpoint_samples` 从"只计数"改为真正参与统计

`experiment/runner.py::build_study_report` 此前收集经济终点样本
（`margin_ratio_bp`, `leverage_bp`）却只把其长度（`n_endpoint_samples`）写进报告，
样本值本身被丢弃——Part 1（终点严重度）因此没有 Part 2 已有的
margin/leverage 均值刻画。

- `metrics/report.py`：把 `build_continuous_part` 里"排除 None 求均值 + null 占比"
  的逻辑抽成共享的 `_sample_stats`，`EndpointPart` 新增
  `mean_margin_ratio_bp`/`mean_leverage_bp`/对应 null 占比字段，
  `build_endpoint_part`/`build_report` 新增 `endpoint_samples` 参数。
- `runner.py::build_study_report` 把已收集的 `endpoint_samples` 真正传给
  `build_report`（此前调用点根本没传这个参数），报告字典新增对应两个均值字段。

新增 `tests/unit/metrics/test_report.py`（6 用例，直接测 `_sample_stats`/
`build_endpoint_part`/`build_report`）+ `test_experiment.py` 新增 1 个端到端用例
（手工构造 `RunResult`，避免依赖真实穿仓场景的偶然性）。均已故障注入验证。

## 3. §2.9/T501：价格冲击 + 滑点指标从零实现

`tasks.md` 里 T501 标"已完成"，但全仓库 grep `impact`/`slippage` 在本轮之前零命中
——指标字典 §3.4（价格冲击）与 §4（滑点）从未实现，只有 T501 声明范围的另一半
（固定间隔采样）是真的。

`metrics/sampling.py` 新增 `compute_price_impact(events, mult)`：按
`taker_order_id` 分组（一笔穿多档的 taker 单会产生多条共享同一 `taker_order_id`
的 `TRADE_SETTLE`），用**首笔**成交的 `valuation_mark_before_half_ticks` 作为
"成交前中间价"（因为撮合与其触发订单在同一事务内，无独立的"下单时刻"记录，
这个近似是精确的，不是权宜），计算成交量加权均价与该中间价的偏离：

- `impact_bp`：指标字典 §3.4 定义的比值口径（整数 bp），买卖方向统一转正号
  （不利方向恒为正）；
- `slippage_cash_units`：指标字典 §4 定义的滑点口径（成交价与下单时中间价之差 ×
  数量），同一正号约定，作为"交易成本 = 手续费 + 滑点"的滑点部分。

**明确未做**：§3.4 提到的"非线性检验"（按分位数分桶、检验 `impact ~ Q^γ` 中 γ 是否
显著偏离 1）是跨订单的统计回归分析，属于报告/统计层范畴，本轮只实现了单笔订单的
`impact(Q)` 指标本身，不包含这个统计检验。

为避免重演"实现了但没接线"的历史模式（本项目此前在 §1.5/§1.10/§2.15/§2.18 等
多处出现过这个问题），额外把 `compute_price_impact` 接入
`runner.py::build_study_report`，报告字典新增 `impact` 段
（`n_taker_orders`/`mean_impact_bp`）。

新增 `tests/unit/metrics/test_sampling.py`（7 用例：单笔冲击、买卖双向符号约定、
不利/有利两种方向的正负对照、多档成交按 `taker_order_id` 分组求 VWAP、两笔不同
订单不串号、`mid_before=0` 边界不崩溃）+ `test_experiment.py` 新增 1 个端到端用例
（用满仓 taker 代理保证产生真实穿档成交）。均已故障注入验证（符号翻转逻辑、
VWAP 分组逻辑各验证一次）。
