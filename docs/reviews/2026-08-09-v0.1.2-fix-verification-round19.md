## 1. 标定路线：从"调参数"改为"从账户数学反推"

第十八轮末尾的四轮尝试（一次性冲击、持续冲击、强制建仓触发正反馈环）均未收尾，
用户要求换思路。核心洞察：与其让代理**通过决策循环**建立杠杆仓位（这个过程会
和价格冲击互相耦合、产生第十八轮那样的失控反馈），不如直接把账户**预置**成
已经开仓的杠杆状态，完全跳过建仓阶段。

具体做法：

1. **`bench/leverage_seed.py`**（新增）：复用 `acceptance-vectors.md` 案例7
   已经逐字节验证过的账户数学（wallet=5000、position=500、entry=100，10x 杠杆，
   价格跌破约 94.7368 即触发 500bp 维持保证金）——直接构造 N 个"受害账户"
   （不挂 `AgentSpec`、不参与决策循环，纯静态仓位），配一个大额对手方账户维持
   C1 恒等式。`stagger_position_step` 让每个受害账户的强平阈值错开一点，避免
   全部账户被同一次外部冲击同时触发（那样测不出连锁）。
2. **`ExperimentConfig.extra_positions`**（新增字段）：`run_one` 新增的第三个
   通用挂钩（继第十八轮的 `extra_accounts`/`extra_events` 之后），直接把账户
   `wallet_units`/`position_units`/`entry_notional_units` 写入引导快照，绕开
   决策循环。信念代理/做市商研究配置不设置此字段时行为不变。
3. 组合 `bench/shock.py` 的持续冲击（第十八轮已验证）+ 20 个错开阈值的受害
   账户，反复调整冲击强度和错开步长，最终在 `position_human=500,
   stagger_position_step=5` + `quantity_units_per_shock=1_500_000, count=150`
   下五项覆盖断言全部通过。

## 2. 意外发现：chain_depth 接线缺口（与 §6.2 同一模式）

五项断言里前四项很快达标，`chained_liquidations`（`chain_depth>=1`）迟迟为 0。
深挖 `book/matching.py::_run_post_batch_risk_check`，发现它调用
`run_phase2_margin_scan` 时**硬编码**传 `parent_chain_id=None`——不管触发这次
批后风控扫描的事件是不是一次强平单自己的成交。而 `ledger/risk.py::
_chain_attrs_for` 的连锁深度递增逻辑本身早就实现且有专属直接单测
（`tests/unit/ledger/test_risk.py::test_chain_depth_increments_for_cascade_onto_
different_agent`），只是**从未被真实调用路径喂过非 `None` 的父链信息**——这意味
着无论标定参数怎么调，`chain_depth` 在任何真实运行里都不可能超过 0，这不是
标定问题，是实现缺口。

修复：`_run_post_batch_risk_check` 判断触发事件是否 `origin == "LIQUIDATION"`，
若是，取该强平账户已有的 `chain_id`/`chain_depth` 作为父链信息传给
`run_phase2_margin_scan`，使这次扫描中新发现的账户正确继承并加深链条。

```python
if event.get("origin") == "LIQUIDATION":
    liquidator = accounts.get(event.get("agent_id"))
    if liquidator is not None and liquidator.chain_id is not None:
        parent_chain_id = liquidator.chain_id
        parent_chain_depth = liquidator.chain_depth
        parent_agent_id = event.get("agent_id")
```
