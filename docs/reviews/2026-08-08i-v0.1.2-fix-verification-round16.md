## 1. 设计讨论确认的三个决策

1. **冻结字段范围**：复用 `run_paired` 已有的 `treatment_field` 概念——除预注册的
   单一处理维度（默认 `leverage_tier`）外，`ExperimentConfig`/`AgentSpec` 全部字段
   进入冻结快照，与 `check_paired_parity` 同一套逻辑思路。
2. **审计记录落地**：写磁盘 JSON Lines 文件（首次给这个仓库引入运行清单持久化），
   违规时追加写入调用方指定路径，默认 `docs/experiments/protocol-audit.jsonl`。
3. **"信念实验区与校准区不重叠"具体检查什么**：只检查处理维度的取值是否与校准
   阶段实际试过的取值集合相交——不是泛化的配置范围重叠检查。

## 2. 实现

新增 `experiment/protocol.py`：

- `ProtocolStage` 枚举：`CALIBRATION → FROZEN_VALIDATION → BELIEF_EXPERIMENT`，
  只能顺序前进；
- `ExperimentProtocol` 有状态对象：
  - `record_calibration_trial(config)`：校准阶段记录处理维度试过的取值，仅
    `CALIBRATION` 阶段可调用；
  - `freeze_calibration(config)`：`CALIBRATION→FROZEN_VALIDATION`，把除处理维度
    外全部字段拍成快照；
  - `enter_belief_experiment(belief_treatment_values)`：`FROZEN_VALIDATION→
    BELIEF_EXPERIMENT`，预注册处理维度取值集合，与校准阶段试过的取值集合求交，
    非空则拒绝（`ProtocolViolation`）；
  - `check_config(config)`：每次实际运行前调用——`CALIBRATION`阶段空操作；
    `FROZEN_VALIDATION`/`BELIEF_EXPERIMENT`阶段核对冻结字段是否漂移，
    `BELIEF_EXPERIMENT`阶段额外核对处理维度取值是否在预注册范围内；任一违规
    `raise ProtocolViolation` 并追加审计记录（fail-stop，不静默继续）。
- `ProtocolViolation`：独立异常类，不复用 `run_paired` 的 `ValueError`——这是
  协议/流程违规，概念上与数据校验错误不同，调用方可以单独捕获。

**接线**（避免这个项目历史上反复出现的"写了但没接线"）：`run_one` 新增
`protocol: ExperimentProtocol | None = None` 参数，`CALIBRATION`阶段自动调用
`record_calibration_trial`，其余阶段自动调用 `check_config`；`run_multi_seed`
新增同名参数透传到每次 `run_one` 调用。

**为避免循环依赖**：把 `ExperimentConfig` 从 `runner.py` 拆到新的 `experiment/
config.py`（`protocol.py` 需要在运行时调用 `dataclasses.fields(ExperimentConfig)`，
不能只用 `TYPE_CHECKING`）。`runner.py` 从 `experiment.config` 导入并原样对外
重新导出，现有 `from market_game_sim.experiment.runner import ExperimentConfig`
调用点不受影响，`pytest -q` 全量通过确认无回归。
