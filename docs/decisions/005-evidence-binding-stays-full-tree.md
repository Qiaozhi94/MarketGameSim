# ADR-005：证据索引绑定策略维持全树哈希，哈希范围收窄降级为观察项

日期：2026-09-02  
状态：Accepted（用户裁决，2026-09-02 复盘对话）  
关联规格：[`../features/0.1/0.1.5-goal-driven-flagship/spec.md`](../features/0.1/0.1.5-goal-driven-flagship/spec.md)  
关联文档：[`../experiments/0.1.5-evidence-index.json`](../experiments/0.1.5-evidence-index.json)、
[`../experiments/0.1.5-t218-acceptance.json`](../experiments/0.1.5-t218-acceptance.json)、

## 背景

0.1.5 证据链把形式化运行绑定到源码：`_source_tree_sha256`
（`src/market_game_sim/showcase/formal.py:79`）对包内全部约 130 个 `.py`
（EOL 归一后）计算单一哈希，写入 T215 manifest/progress；T216 证据索引与
T218/T220 交付产物校验时重算当前哈希，不一致即拒绝（"rerun T215 after source
changes"，`showcase/evidence_index.py:350-360`）。

该设计的代价：任何 `.py` 变更——包括不影响运行结果的呈现层（`replay/`、
`report/`、`showcase/r2-r5` 等）——都会使已提交证据索引失效，触发 T215
（128 block × 16 次运行）+ T216 + T220 全量重跑。R021 检视（2026-08-30）将此
点名为"修复的经济抑制"来源。

由此产生过一项提议：把哈希范围收窄到"结果相关"文件子集（由运行入口 import
闭包推导 + 守卫测试防漂移），使证明力不受呈现层变更影响。

## 决策

1. **维持全树哈希绑定不变。** 绑定的核心价值是"零判断"：全树哈希从不断言
   少于现实，校验规则不需要维护任何人工分类。
2. **哈希范围收窄（原方案 A）降级为观察项，挂起。** 触发条件（写死，满足全部
   三条才重启）：
   - 出现至少一个"可证明不影响运行结果的变更被迫全量重跑"的**真实案例**
     （被点名不等于被兑现，截至本 ADR 时尚未发生）；
   - 重跑成本已实际改变修复行为（修复被推迟或放弃，而非仅被抱怨）；
   - 分类边界可机械化维护（import 闭包自动推导 + 新模块未归类即红的守卫测试），
     不依赖人工记忆。
3. **当前的改进杠杆是把重跑变便宜，而不是把证明变松**：T215 checkpoint 机制
   （`seed-*.json.gz`）已存在，优先投入并行度与停止规则优化，压缩"该付的重跑"
   的实际时长，不动任何证明力。

## 备选方案

- **方案 A（收窄哈希范围 + 守卫测试，本次挂起的观察项）**：优——呈现层变更
  不再触发重跑，消除经济抑制的结构根源；劣——证明力从"哈希说了算"变为"文件
  分类分对了"，误分类会静默削弱证明力且事后难察觉，与 D006（正则门禁）、
  D008（fail-open 门禁）、C013（静默空转门禁）的教训同类：范围/分类型门禁
  是本项目历史上最易出洞的门禁类别。
- **方案 B（分层哈希 + 显式 re-attest）**：优——可审计、保留细粒度溯源；
  劣——机制更重，且"不重跑就重盖章"本身就是检视文化重点打击的门禁旁路面。
- **方案 C（豁免工作流 waiver）**：优——实现最简；劣——把人工判断引入证明链，
  最弱，不予考虑。

## 后果

- 正面：证明力保持零判断；不新增分类维护负担；不引入新的"有洞门禁"风险面；
  R021 式修复重跑的必要性判定维持简单（代码变了就重跑，没有例外条款）。
- 负面：结果无关变更继续承担重跑税，"修复延迟"风险继续存在，靠观察项触发
  条件兜底。
- 后续行动：观察项挂起，触发条件见决策第 2 条。若触发，实施要点已定：
  import 闭包推导结果相关清单 + 守卫测试 + manifest 增加
  `hash_scheme: full-tree-v1 | scoped-v2` 字段以兼容已提交的 0.1.5 产物
  （旧产物按 v1 语义继续有效，避免为归一而重跑一次 2048 局）。
