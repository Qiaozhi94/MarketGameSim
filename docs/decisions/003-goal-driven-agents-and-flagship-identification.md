## 背景

### 1. 旗舰问题要求识别「制度约束是否足以产生涌现式极端状态」

PRD §3.1 的旗舰问题是：在无外生价值冲击的加密式永续市场中，**杠杆上限分布与维持
保证金率是否足以产生自我强化的价格崩盘**。这个问题不应只朝下行一个方向收窄——
[退化状态合同](../contracts/degenerate-states.md) §0 从创建起就并列写着「允许崩盘、
暴涨与流动性枯竭自由涌现」，本 ADR 把旗舰问题显式恢复为三类涌现式极端状态：

| 类型 | 机制 | 对应终点判据（退化状态合同 §4.1） |
|---|---|---|
| **涌现式崩盘** | 多头强平级联下砸价格 | EV-1（触及下界）、EV-2（大幅下行偏离）、EV-4（bid 侧单边清空） |
| **涌现式暴涨** | 空头强平（逼空）级联上拉价格 | EV-2（大幅上行偏离）、EV-4（ask 侧单边清空） |
| **涌现式流动性枯竭** | 代理集体停止报价/成交，市场锁死 | EV-3（连续无成交时长 > T_idle） |

前两者是「跑飞」型正反馈失效，机制互为镜像——账户模型本来就「做空与做多完全对称」
（退化状态合同 §3.2），多头强平砸盘和空头逼空拉盘走的是同一套保证金/强平代码
路径，不需要为暴涨单独建模。这类由杠杆约束本身（无需外生冲击）产生厚尾与波动
聚集的机制，与 Thurner/Farmer/Geanakoplos（2012，*Quantitative Finance*）的经典
结果同族，可作为方法论参照。

第三类是「卡死」型失效而非「跑飞」型——D-4 描述内生锚三种失效形态时用过「锁定」
一词，EV-3 在终点判据表中的标签正是「锁定 / 流动性枯竭」，两处用词并非巧合。它
问的不是「价格能不能自我强化地跑飞」，而是「杠杆/保证金制度能不能自我强化地让
市场停摆」——这是与崩盘/暴涨平行、但机制不同的第三个研究目标。

三类现象共享同一个「足以」判据，本 ADR 后续统一处理，不再逐类重复：

1. 代理从零初始仓位经正常决策与撮合内生建仓；
2. 杠杆上限与保证金制度作为约束介入，而不是直接命令代理扩大仓位或收缩活动；
3. 崩盘、暴涨、流动性枯竭三类现象的启动、传播与强平反馈均可由事件因果链区分方向；
4. 无杠杆或低杠杆对照只改变预注册的制度处理，不同时改变代理偏好；
5. 若三类现象都未出现，也能形成「在该模型族与参数区间内不足以产生」的有效负面
   结论；三类现象出现的相对频率与严重度差异（例如崩盘是否比暴涨更容易发生）本身
   也是一项待报告的结果，不得预设对称。

### 2. 当前目标仓位公式把处理变量写进了行为规则

当前代理策略合同规定：

```text
max_notional    = equity × 10000 / initial_bp
max_position    = floor(max_notional / mark)
target_position = trunc(signal_bp × max_position / 10000)
```

其中 `initial_bp` 由 `leverage_tier` 决定。因此，改变杠杆档位同时改变了：

- **制度可行域**：订单最多能获得多少杠杆；
- **代理目标**：在同一个信号下主动追求多大的仓位。

若高杠杆组出现更多强平或崩盘，无法区分结果来自「约束放宽后风险内生积累」，还是来自
「模型直接要求高杠杆代理建立更大仓位」。这使处理变量与行为政策纠缠，旗舰问题的因果
归因不成立；增加种子、参数点或替代信号映射不能消除该结构性混淆。

### 3. 内生 EWMA 合同与当前实现不一致

代理策略合同把均值回复锚定义为逐代理、逐成交更新的内生 EWMA。当前信号路径实际使用
`initial_price_ticks` 作为回归锚，没有维护逐代理 EWMA 状态。

固定初始价是运行配置参数，不是代理互动产生的动态状态。该漂移会人为提供共同回复中心，
并使结果依赖初始价格参数。补齐 EWMA 能修复合同一致性，但**不能单独解决** §2 的杠杆
处理混淆。

### 4. 当前退出证据验证了工程链路，没有建立旗舰结论

0.1.2 的真实代理示范运行在 3x/10x 两组均未产生经济终点或强平。0.1.3 的强平与连锁
证据使用了预置在高杠杆状态的受害账户和持续同方向市价冲击；其退出报告也明确声明旗舰
终点率为 0，效应代理是强平发生率，不产出旗舰信念结论。

这些证据足以支持撮合、保证金、强平、因果日志、扫描和报告管线的工程可用性，但不足以
支持「杠杆/保证金足以使崩盘从代理互动中涌现」。现有里程碑 `status: done` 因而混合了
工程完成与研究结论完成两种不同语义。

## 决策

### 1. 采用目标驱动代理，并将目标形成与制度约束分层

信念代理的决策管线改为：

```text
agent preferences + private state + permitted market observations
    → goal formation
    → desired exposure / desired inventory
    → leverage and margin feasibility constraint
    → executable target
    → order intents
    → admission and matching
```

冻结以下不变量：

- `desired_exposure` / `desired_position` **不得读取** `leverage_tier`、`initial_bp`、
  `maint_bp` 或「本组是 control/treatment」之类实验臂信息；
- 杠杆和保证金参数只能在 `feasibility constraint`、订单准入、风险扫描与强平阶段生效；
- 代理偏好、风险预算、目标形成参数与随机语义键在配对实验两臂保持相同；
- 约束不绑定时，改变杠杆上限不得改变订单意图；约束绑定时，只允许改变可执行规模；
- 做市商可使用库存目标，但库存目标与报价风险政策同样不得由实验臂的杠杆档位派生。

目标驱动不等于理性最优化或在线学习。v0.1 仍允许固定参数、有限理性的规则目标；本 ADR
只要求「代理想做什么」与「制度允许它做到什么」在接口和证据上可区分。

### 2. EWMA 降为可替换的内生观测机制，不再承担共同外部目标

- 实现代理策略合同承诺的逐代理 EWMA：只消费该代理自上次观察以来可见的成交事件；
- `initial_price_ticks` 只用于 EWMA 冷启动，不得在有成交后继续作为固定回复中心；
- EWMA、动量、羊群、盘口与噪声可以参与目标形成，但任何单一信号族都只是可替换模型族；
- 现有五因子线性/阈值目标仓位策略保留为历史 baseline，但在完成解耦前不得作为旗舰
  因果结论的主模型；
- 0.1.3 的稳健性矩阵需要在目标驱动模型落盘后重新预注册，旧结果不自动迁移为新模型证据。

### 3. 将「自发涌现」与「压力放大」拆成两个独立实验族

#### 3.1 自发涌现实验（旗舰实验）

该实验用于回答 PRD §3.1：

- 全部普通代理从零仓位开始，经正常订单流内生建仓；
- 禁止 `extra_positions`、预置杠杆受害者、持续定向 forcing orders 或结果导向的冲击调参
  （无论方向导向崩盘还是暴涨）；
- control/treatment 的唯一处理差异为预注册的杠杆/保证金制度字段；
- 随机噪声与异质偏好可作为随机创新，但不得携带预定的共同方向或崩盘/暴涨脚本；
- 主要终点必须同时刻画价格崩盘、价格暴涨、流动性枯竭三类经济终点与其强平反馈，
  不得用单独的强平发生率替代，也不得只报告其中一个方向。

允许且必须报告的负面结论包括：三类现象均未出现、两臂同样出现、只有极窄参数区间
出现、效应依赖特定目标模型族，或三类现象之间存在方向不对称（如崩盘显著比暴涨
更易发生）——不对称本身是有效结果，不预设对称也不得为凑对称而调整参数。

#### 3.2 压力放大实验（独立研究问题）

该实验回答「杠杆与强平把同一个外生订单冲击放大多少」：

- 冲击路径、规模、方向、开始与结束时刻必须预注册并在配对两臂逐事件相同；
- 冲击必须有限，禁止持续到目标结果出现为止；
- 报告必须使用「冲击放大」「韧性」或「条件响应」措辞；
- 预置账户只允许用于组件/覆盖试验；若用于压力实验，结论必须显式条件于该初始风险结构；
- 压力实验不得作为自发涌现实验的替代退出证据。

### 4. 增加目标、约束与触发来源的可审计证据

每次代理决策至少记录以下版本化字段，具体 Schema 在实施规格中冻结：

| 证据 | 含义 |
|---|---|
| `goal_model_id` / `goal_model_version` | 使用的目标模型及版本 |
| `desired_position_units` | 应用杠杆/保证金约束前的目标 |
| `executable_position_units` | 应用可行域约束后的目标 |
| `constraint_binding` / `constraint_reason` | 约束是否绑定及原因 |
| `trigger_provenance` | `ENDOGENOUS_AGENT`、`LIQUIDATION` 或 `EXOGENOUS_STRESS` |

独立验证器必须能从成交回溯到目标、约束、订单、成交、保证金判定与后续强平。旗舰终点
只有在触发来源和传播链满足预注册定义时才计数；外生压力直接触发的一组并列强平不能被
误记为内生连锁。

### 5. 分离工程状态与研究声明状态，不抹除历史交付

0.1.2 与 0.1.3 不回滚已通过的工程成果，也不删除原始证据。状态模型新增两个维度：

```yaml
engineering_status: done
research_claim_status: not_established
```

在目标驱动模型、旗舰预注册和正式运行完成前：

- 现有 0.1.2/0.1.3 证据统一标注为 engineering demonstration；
- 不得用 `status: done` 推导「旗舰问题已回答」；
- 0.1.3 的扫描、配对、留出与负面结果框架可以复用；
- 撮合、账本、保证金、强平、事件日志和报告基础设施继续作为受保护的 L1/L3 资产；
- 新研究结论必须引用新模型版本、新预注册和新运行证据，不得混合旧示范数据。

## 验收门槛

本 ADR 从 Proposed 转为 Accepted 后，旗舰研究重新具备签收资格前必须满足：

1. 静态检查或架构测试证明目标形成层不依赖杠杆、保证金与实验臂字段；
2. 正反例测试证明非绑定约束不改变订单，绑定约束只裁剪可执行目标；
3. 逐代理 EWMA 的合同、实现、事件消费边界与确定性测试一致；
4. 自发涌现与压力放大各有独立预注册、运行入口、主要终点和报告措辞守卫；
5. 至少一次正式自发涌现实验从零仓位运行，对崩盘、暴涨、流动性枯竭三类经济终点
   分别诚实产出支持、不支持或证据不足结论，并报告三者之间的方向对称性。

## 备选方案

### 方案 A：维持现有 signal × leverage-cap 目标仓位，只增加模型族扫描

优点：无须重构代理接口，可直接复用 0.1.3 结果。  
缺点：扫描只能测量不同信号规则下同一处理混淆的敏感性，不能把杠杆约束与目标规模分开；
无法回答旗舰问题。排除。

### 方案 B：只补齐逐代理 EWMA

优点：修复合同/实现漂移，移除固定初始价作为持续回复中心。  
缺点：`leverage_tier` 仍直接放大目标仓位，因果混淆保留；只能作为本决策的一个实施项，
不能作为完整方案。排除。

### 方案 C：目标驱动代理与制度约束分层（已提议）

优点：处理变量只通过制度可行域影响行为；支持有效负面结论；同一目标模型可用于自发与
压力实验；现有 L1/L3 基础设施可复用。  
缺点：需要重构代理接口、事件 Schema 与研究预注册，并重新运行 0.1.2/0.1.3 的研究证据。

### 方案 D：废弃现有实现并重写整个仿真器

优点：可以从头统一模型。  
缺点：问题集中在代理目标层和研究识别，不在撮合、账本或实验基础设施；全量重写会丢失
大量已验证资产并引入新风险。排除。

## 后果

- **正面**：杠杆上限重新成为可识别的制度处理；自发崩盘与外生冲击放大不再混为一个
  结论；目标、约束和强平之间形成可审计因果链；无效应成为可信研究结果。
- **负面**：0.1.2/0.1.3 的研究部分需要重新预注册和运行；事件日志字段增多；目标模型
  的选择仍是模型假设，需要至少两个结构不同的目标族做稳健性检查。
- **后续行动**：接受本 ADR 后，先更新 PRD/代理合同/0.1.2/0.1.3 的状态语义，再拆分
  实施 feature；代码改动不得先于目标接口、实验处理和主要终点的规格评审。

## 待审问题

1. `desired_exposure` 的 v0.1 首个目标模型采用风险预算启发式、效用函数，还是两者并行？
2. `maint_bp` 是否也应完全排除在普通代理目标信息集外，仅允许风险告警策略读取？
3. 自发涌现实验允许哪类无方向随机流动性需求，如何证明其不是隐蔽外生冲击？
4. 是否增加「强平通过订单簿」与「强平由无价格冲击的外部承接池吸收」对照，以识别
   强平卖单的价格反馈中介效应？
5. 0.1.2/0.1.3 是修改现有 `status`，还是保留 `done` 并新增双状态字段？
