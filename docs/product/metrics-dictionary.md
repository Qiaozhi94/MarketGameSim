## 1. 术语

### 1.1 事件（Event）

**日志中的一条全序记录。** 分两类（事件 Schema §1.4）：**队列事件**从队列弹出并
执行一个原子事务；**事务记录**在事务内生成、直接写入日志，不再被执行。
队列调度使用 `(timestamp, priority_class, enqueue_seq)`，日志、摘要与重放使用
`(timestamp, transaction_seq, record_index)`（KR-003）。事件类型清单与优先级见
[`../contracts/event-schema.md`](../contracts/event-schema.md)。

**事件是内核工作量的计量单位**，KPI-004 / NFR-003 的性能门槛以「已处理事件数」
表达。

### 1.2 代理动作（Agent Action）

**代理提交的一个订单意图——一次下单或一次撤单。**

注意代理动作与决策循环不是一对一：一次决策循环可能产生 0 个动作（观察后不交易）、
1 个动作，或多个动作（做市商双边报价产生 2 个）。因此**代理动作不适合作为性能
基准的计量单位**，只作为辅助统计量报告。

性能门槛以基准配置 `benchmarks/BENCH-001.yaml` 的固定事件数表达，而非代理动作数。

### 1.3 决策循环（Decision Cycle）

代理从被唤醒观察到产生动作意图的完整过程：观察 → 更新内部状态 → 生成意图 →
提交动作（可能为空）。

### 1.4 逻辑时间与事件时间

- **逻辑时间（Logical Time）**：内核的整数纳秒时间戳（KR-002）。用于表达延迟、
  观察频率和事件先后。
- **事件时间（Event Time）**：以事件计数或成交计数为轴的离散时间。用于定义与市场
  活跃度自适应的量（如锚的半衰期）。

两者不可混用。凡涉及时间窗口的指标必须声明其所用的时间轴。

### 1.5 半衰期（Half-life，τ）

内生锚 EWMA 权重衰减至 1/2 所经过的时间（001 / D-4）。

**τ 以成交笔数计（事件时间轴），而非逻辑时间。** 理由：锚是价格统计量，价格仅在
成交时更新；无成交时锚不应自行漂移。该选择使锚的记忆随市场活跃度自适应。

EWMA 平滑系数：`α = 1 - 2^(-1/τ)`，每笔成交按 `anchor ← α·price + (1-α)·anchor`
增量更新。

**敏感性检查项**：以成交笔数计的半衰期，其对应的墙钟记忆长度随活跃度变化。M2 参数
扫描须附带一次以逻辑时间计的对照，确认结论不依赖该选择。

### 1.6 maker 与 taker

- **maker**：订单进入订单簿提供流动性后被**被动**成交的一方；
- **taker**：主动消耗簿上流动性的一方。

费率分别配置（FR-003）。同一笔成交的双方分别按各自身份计费。

### 1.7 tick

最小价格变动单位。所有价格必须为 tick 的整数倍，内部以整数 tick 计数存储，避免
浮点比较破坏价格时间优先的确定性。

### 1.8 最小单位（tick_size / min_quantity / cash_unit）

领域层与事件日志中的价格、数量、现金、名义金额、费用与持仓成本**一律为最小单位
整数**，禁止浮点（[ADR-001](../adr/001-numeric-and-serialization-contract.md) §1）。
`cash_unit` 初值 `1e-8`。

配置校验断言 `tick_size × min_quantity` 是 `cash_unit` 的整数倍，因此**成交名义
金额不产生任何舍入**；全系统唯一的舍入点是手续费，方向恒不利于代理、有利于交易所
（ADR-001 §3）。本文所有以十进制书写的指标定义，均指其最小单位整数在报告层还原后
的值。

### 1.9 K 线周期（Q-012）

**K 线以逻辑时间定义，基础周期 `bar_ns = 60 秒`**，可聚合为 5 / 15 / 60 分钟。

选逻辑时间而非成交笔数的理由：技术因子（动量、均线、MACD 一族）与统计检验都假定
等间隔观测；按成交笔数分箱会使活跃时段被过度加权，同一「100 笔」在不同活跃度下
跨越的真实时间差异极大。

**与半衰期 τ 的轴不同，不可混用**：τ 以成交笔数计（§1.5，事件时间轴），因为锚是
价格统计量、只在成交时更新；K 线以逻辑时间计（§1.4），因为它服务于等间隔检验。
两者换算需经该运行的实测平均成交率，且换算结果逐运行不同。

每根 K 线记录：`open` / `high` / `low` / `close` / `volume` / `trade_count`。
**周期内无成交时不跳过该根**，`open=high=low=close=` 前一根的 `close`，`volume=0`，
并计入前值填充比例（§2）——跳过空 K 线会使序列不再等间隔，破坏检验前提。

第一版为 24/7 连续市场，K 线序列不间断。股票式制度引入后须补充收盘跨越与隔夜跳空
的处理规则。

## 2. 采样约定

**统计特征检验（厚尾、自相关、波动聚集）要求等间隔采样。**

价格序列按**固定逻辑时间间隔 Δt** 采样，而非按成交笔数。理由：自相关与波动聚集的
标准检验假定观测等间隔；按成交采样会使活跃时段被过度加权，检验结果不可解释。

- **Δt 初值 = 1 秒逻辑时间**（MD-001）；
- 采样点无成交时，价格取该时刻的**最近成交价**（前值填充）；
- 前值填充的比例须随报告输出。**填充比例超过 30% 时该运行的统计检验不可采信**——
  说明 Δt 相对市场活跃度过细，须调大 Δt 后重跑；
- 单次研究运行须产生至少 2000 个采样点，以支撑自相关与厚尾检验。

**研究运行的终止条件必须按采样点数（或等价的逻辑时长）设定，不得沿用性能基准的
事件数口径。** Δt = 1 秒时 2000 采样点意味着 ≥ 2000 秒逻辑时间；而性能基准的
`max_events: 100000` 按其代理构成粗算仅对应数百秒逻辑时间，采样点数差一个数量级。
两者用途不同——性能基准要的是**跨机器完全一致的工作量**（故按事件数终止），研究
运行要的是**足够的统计样本**（故按采样点终止）。混用会使统计检验在样本不足的序列
上进行。终止条件与实际采样点数须随每次研究运行记录，未达 2000 点的运行不得进入
统计检验。

## 3. 市场层指标（PR-014）

### 3.1 价格

| 指标 | 定义 | 未定义情形 |
|---|---|---|
| 最优买价 `best_bid` | 买方最高挂单价 | 买方无挂单时未定义 |
| 最优卖价 `best_ask` | 卖方最低挂单价 | 卖方无挂单时未定义 |
| 中间价 `mid` | `(best_bid + best_ask) / 2` | 任一侧空时未定义 |
| 最近成交价 `last` | 最近一笔成交的价格 | 尚无成交时未定义 |
| **估值标记价** `valuation_mark` | 用于权益、未实现 PnL 与会计桥接（§5.2）。取 `mid`；`mid` 未定义时退化为 `last` | 两者皆无时未定义 |
| **风险标记价** `risk_mark` | 用于保证金与强平判定（账户合同 §3.2）。**恒取 `last`**；首笔成交前取 `initial_price` | 永不未定义 |

**两个 mark 不可混用。** `risk_mark` 只用 `last`，因为挂单与撤单会移动 `mid`，
若用于强平判定，一次报价就可能触发强平（代理策略 §3.3）；`valuation_mark` 用 `mid`，
因为它是更好的公允价估计，且**若估值也用 `last`，会使 §5.2 的 `Spread` 与 `Impact`
恒相互抵消**（成交后 `last` 必等于成交价），两个指标同时失去意义。

事件日志须记录 `valuation_mark_before` 与 `valuation_mark_after`
（事件 Schema §4.2），使会计桥接可仅凭日志重放。

未定义值不得以 0 或前值静默替代，并计入「无效报价时间占比」。其表示分层
（ADR-001 §6）：

- **领域层**：不存在该值（整数表示下 NaN 不可构造），FR-018 的「不得产出未定义
  状态」指这一层；
- **事件日志（JSONL / Parquet）**：写 `null`。JSON 标准无 NaN 字面量，写 NaN 会
  产出非标准数据或序列化失败；
- **分析层**：读取后将 null 映射为 NaN 再做统计。本文其余各处的 NaN 表述仅在这一层
  有效。

### 3.2 收益与波动

- **对数收益**：`r_t = ln(P_t / P_{t-1})`，`P` 取按 §2 采样的最近成交价。
- **已实现波动率**：窗口 W 内对数收益的标准差，`σ_W = std(r_{t-W+1..t})`。
  W 为配置项，报告须声明取值。
- **绝对收益序列**：`|r_t|`，用于波动聚集检验。

采用成交价而非中间价计算收益，以避免报价抖动引入的伪波动；该选择须在报告中声明。

### 3.3 流动性

| 指标 | 定义 |
|---|---|
| 报价点差 | `best_ask - best_bid` |
| 相对点差 | `(best_ask - best_bid) / mid` |
| 有效点差 | `2 × |P_trade - mid_before|`，`mid_before` 为成交前一刻的中间价（日志字段 `mid_before_half_ticks`，以半 tick 为单位的整数；任一侧空时为 null，该笔不计入） |
| 深度(k) | 距最优价 k 个 tick 以内的累计挂单数量，买卖两侧分别统计 |
| 成交量 | 采样区间内成交数量之和 |
| 撤单率 | 撤单动作数 / 下单动作数 |

有效点差衡量实际交易成本，报价点差衡量名义成本；两者差异反映簿的深度结构，须分别
报告，不得互相替代。

### 3.4 价格冲击

对规模为 Q 的主动成交（taker）：

```text
impact(Q) = (成交加权均价 - 成交前中间价) / 成交前中间价
```

买方主动取正号，卖方主动取负号后统一为正值口径。

**非线性检验**：将 Q 按分位数分桶，报告各桶的 `impact` 均值与置信区间，并检验
`impact ~ Q^γ` 中 γ 是否显著偏离 1。PRD §12 要求的「合理非线性」以此判据表达。

## 4. 代理层指标（PR-015）

所有指标须按 FR-016 输出**时间序列**，而非仅终值。

| 指标 | 定义 |
|---|---|
| 钱包 | 可用钱包 + 挂单占用保证金 |
| 仓位 | 合约仓位（多头为正，空头为负） |
| 权益 | `钱包 + 未实现 PnL` |
| 已实现 PnL | 平仓部分的累计损益，不含未平仓部分 |
| 未实现 PnL | `仓位 × mark − 开仓成本`（账户合同 §2.2） |
| 总 PnL | 已实现 + 未实现 |
| 交易成本 | 累计手续费 + 累计滑点（滑点 = 成交价与下单时中间价之差 × 数量） |
| 最大回撤 | 权益曲线上 `max(峰值 - 当前值) / 峰值` |

分代理类型汇总时，报告组内均值、中位数与分散度，不得只报均值——异质代理的均值
可能掩盖组内分化。

### 4.1 杠杆与强平指标

| 指标 | 定义 |
|---|---|
| 权益 | `钱包 + 未实现盈亏`（可为负，见穿仓） |
| 保证金占用 | `名义价值 × maint_bp / 10000`（账户合同 §3.2） |
| **保证金率** | `权益 × 10000 / 名义价值`，整数万分数；**无仓位时为 null**（账户合同 §3.2） |
| 杠杆率 | `名义价值 / 权益`；初始恒为 0，是内生结果而非初始条件 |
| 强平量占比 | `origin=LIQUIDATION` 的成交量 / 总成交量 |
| **连锁深度** | 一次强平引发的后续强平的最大传导层数：由强平成交推动价格、致使其他账户跌破维持线的次数，逐层计数 |
| 连锁规模 | 单个连锁事件中被强平的账户数与总强平金额 |
| 穿仓额 | `exchange_risk_pnl_units` 的累计值，**有符号，损失为负**（账户合同 §5.2） |

**保证金率用整数万分数**（如 500 表示 5%）是 ADR-001 §1 的直接推论：若用浮点，
「恰好等于维持线」的账户在不同平台上可能得到不同的强平判定，NFR-001 随即失效。

连锁深度的计数规则须在实现中定死：一次强平成交后，**在同一时间戳内**因该成交引发的
强平记为深度 +1；跨时间戳的后续强平若中间无其他代理主动成交，仍计入同一连锁。

## 5. 守恒不变量（PR-004 / SC-001）

以下**两条守恒等式**必须在每个事件之后成立，是撮合正确性测试的核心断言：

```text
[C1] 仓位恒等式
Σ position_units(t) ≡ 0

[C2] 价值守恒（联合恒等式）
Σ (wallet_units − entry_notional_units)(t)
    + 交易所费用_units(t) + exchange_risk_pnl_units(t)
    = Σ wallet_units(0)
```

账户模型为**线性永续合约**（[账户与保证金合同](../contracts/margin-and-account.md)）：
没有「现金 + 库存」的现货交割，只有钱包余额与合约仓位。

**`Σwallet` 与 `Σentry_notional` 各自都不守恒**——仓位跨价换手时，已实现盈亏从
`entry_notional` 转移到 `wallet`。守恒的是**两者之差**（账户合同 §2.3 有反例与验算）。

`exchange_risk_pnl_units` **有符号，交易所承担的损失记负数，在 C2 中以加号进入**。
核销穿仓时 `Δwallet = +L`、`Δrisk = −L`，一加一减恰好抵消，C2 守恒。写成减号会得到
`ΔC2 = +2L`（账户合同 §2.3）。

**两式为整数精确相等（001 / SC-001），不得写成浮点容差断言。** 容差会把 KPI-001 从
正确性断言降级为一个需要调参的隐藏阈值。整数域的精确成立由 ADR-001 保证：名义金额
无舍入，费用舍入方向恒有利于交易所，故舍入余数恒有归属。风险账户承接穿仓造成的
负现金（001 / D-2），使 C1 在代理现金为负且无力偿还时仍然成立。

### 5.1 权益与 mark 无关

由 C1 可推出：

```text
Σ equity = Σ wallet + mark × Σ position − Σ entry_notional
         = Σ (wallet − entry_notional)        （因 Σposition ≡ 0）
```

即 **`Σequity` 不随 mark 变动**，恒等于 C2 左侧第一项。这是永续相对杠杆现货的核心
收益：现货下净持仓非零，`Σ权益` 随价格漂移；永续下多空两侧的重估自动抵消。

已验算：5 代理 6 笔跨价换手（含反向平仓与手续费），`mark` 取 50 / 100 / 200 时
`Σequity` 恒为 4997.366。

**守恒测试必须包含三代理跨价换手**（A 建仓 → A 平给 C → B 仍持仓）。只用一对多空
且从不更换对手方的用例，会让已被推翻的「Σwallet = 常数」看起来成立。

**个体账户另须桥接检验**（§5.2）：全局恒等式捕捉不到「A 少了 B 多了」之外的错误，
个体桥接才能定位到具体账户。

### 5.2 PnL 会计桥接（FR-017）

权益变动必须被**完整、互斥地**分解为五项，**残差恒为 0**：

```text
Δequity = Spread + Impact + Revaluation + Funding − Fees
```

其中 `signed_qty` 买入为正、卖出为负；**`vm` 为估值标记价 `valuation_mark`（§3.1），
不是风险标记价**：

| 项 | 公式 | 含义 |
|---|---|---|
| `Spread` | `signed_qty × (vm_before − trade_price)` | 相对成交前公允价的执行优劣 |
| `Impact` | `signed_qty × (vm_after − vm_before)` | 本笔成交造成的**即时**公允价移动对**新增**仓位的影响 |
| `Revaluation` | `position_before × (vm_after − vm_before)` | **原有**仓位的重估 |
| `Funding` | 资金费收付 + 穿仓核销（**有符号**，收入为正） | 第一版资金费为 0 |
| `Fees` | 手续费（有符号，返佣为负） | ADR-001 §3 |

**`Funding` 存储有符号的 PnL 贡献，在总公式中以加号出现**，不是「正的成本再相减」
——后者会与账户合同 §5.3「违约项为负」形成双重反号。

#### 5.2.1 推导

由永续的权益定义直接展开（**不是** `cash + position × mark`，永续没有现金交割）：

```text
equity  = wallet + position × vm − entry_notional
Δequity = Δwallet + Δ(position × vm) − Δentry_notional
```

代入 `Δwallet = realized_pnl − fees + funding`，并按「新增仓位 / 原有仓位」拆分
`Δ(position × mark)`，即得上表五项。互斥性由此是**证明**出来的：`Spread` 与
`Impact` 以 `vm_before` 为分界，区间不相交；`Impact` 只作用于新增仓位，
`Revaluation` 只作用于原有仓位。

**必须用 `valuation_mark` 而非 `risk_mark`**：若用 `last`，则 `vm_after` 恒等于
成交价，于是

```text
Spread + Impact = q×(last_before − price) + q×(price − last_before) ≡ 0
```

两项永远抵消，虽然恒等式仍成立，但价差与冲击**同时失去研究意义**。

#### 5.2.2 已验算的七种情形

以下均以 `Decimal` 精确验算，残差为 0：

| # | 情形 | `vm_before → vm_after` | Δequity |
|---|---|---|---|
| ① | 同向开仓 `0 → +10` | 100 → 100.5 | +4.5000 |
| ② | 同向加仓 `+10 → +15` | 100 → 102.5 | +27.2450 |
| ③ | 部分平仓 `+15 → +5` | 103 → 104.5 | +26.9750 |
| ④ | 跨价完全平仓 `+5 → 0` | 104 → 109.5 | +29.7250 |
| ⑤ | **反向翻仓** `+5 → −5` | 104 → 97.5 | −27.9900 |
| ⑥ | 空头部分平仓 `−10 → −4` | 98 → 95.5 | +27.7150 |
| ⑦ | 含资金费转移 | 100 → 101.5 | +11.3990 |

`vm_after` 与成交价不相等——这正是 `valuation_mark` 取 `mid` 的意义所在。

#### 5.2.3 手工验算示例

**示例 A：同向开仓**（`wallet=1000`，`position=0`，`vm_before=100`）
买入 10 @ 100，成交后 `vm_after=100.5`（成交推动盘口，`mid` 上移），taker 5 bps：

```text
fee    = 10 × 100 × 0.0005 = 0.5
wallet = 1000 − 0.5 = 999.5        # 开仓不扣名义本金，只扣手续费
entry  = +1000,  position = +10
equity_before = 1000 + 0×100 − 0     = 1000
equity_after  = 999.5 + 10×100.5 − 1000 = 1004.5
Δequity = +4.5

Spread      = +10 × (100 − 100)   =  0
Impact      = +10 × (100.5 − 100) = +5
Revaluation =   0 × (100.5 − 100) =  0
Fees        = 0.5
合计 = 0 + 5 + 0 + 0 − 0.5 = +4.5            ✓ 残差 0
```

**示例 B：反向翻仓**（`wallet=1000`，`position=+5`，`entry=+510`，`vm_before=104`）
卖出 10 @ 98（平掉 +5、反向建 −5），成交后 `vm_after=97.5`：

```text
avg_entry    = 510 / 5 = 102
realized     = 5 × (98 − 102) = −20          # 平掉的 5 手
entry_after  = −5 × 98 = −490                # 新建的空头
fee          = 10 × 98 × 0.0005 = 0.49
wallet       = 1000 − 20 − 0.49 = 979.51
equity_before= 1000 + 5×104 − 510          = 1010
equity_after = 979.51 + (−5)×97.5 − (−490) = 982.01
Δequity      = −27.99

Spread      = −10 × (104 − 98)    = −60
Impact      = −10 × (97.5 − 104)  = +65
Revaluation =  +5 × (97.5 − 104)  = −32.5
Fees        = 0.49
合计 = −60 + 65 − 32.5 + 0 − 0.49 = −27.99   ✓ 残差 0
```

注意 `Spread + Impact = +5 ≠ 0`——若 `vm` 取 `last`，`vm_after` 必为 98，
两项会恰好抵消。

**示例 C：穿仓核销**（承账户合同 §8 示例 4）
钱包 −4635.2、仓位已归零。核销事件中：

```text
Funding（含核销） = +4635.2        # 代理侧：免除的损失，有符号为正
Δequity          = +4635.2        # 权益从 −4635.2 归零
合计 = 0 + 0 + 0 + 4635.2 − 0     ✓ 残差 0
```

同一事件中交易所侧 `exchange_risk_pnl_units` 减少 4635.2（负值），全局 C2 守恒。

#### 5.2.4 已知界限：延迟冲击无法分离

`Impact` 只捕捉**即时**冲击（`vm_before → vm_after`）。成交后数秒内的价格漂移
属于**延迟冲击**，它会落进后续事件的 `Revaluation`，逐事件会计中无法与普通价格变动
区分。要研究延迟冲击须用 markout 分析（成交后 N 秒的价格相对成交价），那是独立于
会计桥接的统计工作。报告不得把 `Impact` 称为「市场冲击成本」——它只是即时部分。

**「交易所累计费用」是有符号量，可以为负**（负 maker 费率下交易所向 maker 付钱，
净费用取决于 `maker_bps + taker_bps` 的符号，ADR-001 §3）。守恒等式要求的是费用
账户按实际有符号金额记账，不是它非负——把非负性误当成守恒前提，会拒绝合法的补贴型
费率实验。

**手续费必须在下单时预冻结**（按上界，ADR-001 §4）。否则 taker 单成交后扣费可能使
现金为负，违反 FR-003 的约束语义并破坏第一条等式。

## 6. 稳定性诊断指标（001 / D-4）

用于识别内生锚的三种失效形态，均复用既有指标，不新增采集：

| 失效形态 | 诊断指标 | 判据 |
|---|---|---|
| 锁定 | 均值回复代理的成交量占比 | 接近 0 表明锚失效 |
| 发散 | 对数价格相对初值的偏离、触界样本比例 | 见退化状态定义文档 |
| 周期振荡 | 收益序列自相关函数 | 在 lag ≈ τ 处出现显著峰，判定为参数产物 |

## 7. 参数取值

以下初值已写入 `benchmarks/BENCH-001.yaml`。取值变更须记录并评估对既有实验可比性
的影响。

| 编号 | 参数 | 初值 | 依据 |
|---|---|---|---|
| MD-001 | 采样间隔 Δt | 1 秒逻辑时间 | 使典型运行产生 ≥ 2000 采样点，且前值填充比例可控 |
| MD-002 | 波动率窗口 W | 30 个采样点 | 约 30 秒窗口；短于 20 点估计噪声过大，长于 50 点掩盖聚集 |
| MD-003 | 深度距离 k | ±10 tick | 覆盖做市商典型报价范围，同时不受远端稀疏挂单干扰 |
| MD-004 | 冲击分桶切点 | 20/40/60/80/95 分位 | 前四点等分，第五点单独隔离最大 5% 的订单——非线性主要出现在尾部 |

MD-002 与 MD-003 的初值在 M2 首次验证后可回写调整；MD-001 一经用于正式实验即冻结，
因为改变采样间隔会使既有的自相关与波动聚集结果不可比。
