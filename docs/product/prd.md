## 1. 产品摘要

MarketGameSim 是一个本地运行、多代理参与、限价订单簿驱动的加密现货市场博弈仿真
实验环境。它让研究者能够配置不同类型的散户、做市商、大资金执行者和具备订单流信息
优势的代理，观察它们的订单如何共同形成价格、流动性和财富转移，并通过可复现的对照
实验解释结果。

模型中不存在外生基本面信息通道：价格路径完全由订单流互动内生产生。这使产品可以
集中研究市场行为本身，以及价格走势如何反过来影响交易者决策（见
[ADR-003](../adr/003-crypto-spot-market-without-fundamentals.md)）。

本产品首先是研究与学习工具，而不是实盘交易系统、价格预测器或投资建议生成器。

## 2. 背景与问题

现实市场中的价格变化是订单、资金、信息、交易约束和参与者预期共同作用的结果。
仅观察 K 线或最终收益，通常无法可靠回答以下问题：

- 不同类型参与者分别对价格和流动性产生了什么影响？
- 大资金的优势来自资金、信息、速度还是执行方式？
- 当技术交易者在市场中的占比变化时，波动聚集强度、价格冲击非线性和崩盘频率
  如何变化？在何种参数区间内，趋势跟随群体的净收益为负？
- 某种策略的收益是稳定机制，还是特定参数和随机路径造成的偶然结果？
- 交易规则和风险约束改变后，财富转移和市场质量如何变化？

注意第三个问题的提法：它询问的是技术交易者**占比变化带来的市场后果**，而不是
"价格走势是否影响交易者"。后者在代理规则中已被写死，无法被实验否定（见 §13 首行
风险与 [`methodology.md`](methodology.md) §11）。

现有回测工具主要在历史价格上执行单一策略，难以表达参与者之间的双向市场影响；
通用多代理框架又缺少订单簿、账户守恒和金融市场验证。本项目拟在两者之间提供一个
小型、透明、可修改且具备研究纪律的实验平台。

### 2.1 方法论背景：基于代理的计算经济学

MarketGameSim 采用基于代理的计算经济学（Agent-Based Computational Economics，ACE）
方法，将散户、做市商、大资金执行者和具备订单流信息优势的代理建模为具有独立状态、
信息集、决策规则、目标和约束的自主代理。

代理根据有限且可能带有噪声的信息持续观察市场、提交或撤销订单，并在成交后更新现金、
持仓和决策状态。市场价格不由系统预先生成，而是通过代理订单在限价订单簿中的交互与
撮合内生形成。模型中不存在外生基本价值过程，均值回复力由锚定内生长周期价格统计量
的代理提供。

该方法用于研究微观参与者行为如何产生价格发现、流动性变化、波动聚集、羊群效应、
价格冲击和财富转移等宏观市场现象。MarketGameSim 同时引入博弈分析，用于描述不同
参与者的目标、能力和策略关系；代理仿真则观察大量异质、有限理性的参与者持续互动后
产生的动态结果。

仿真中的涌现现象不自动代表真实市场规律。所有结论必须限定在明确的模型假设和参数
范围内，并经过多随机种子、参数扫描、对照实验及市场统计特征验证，避免将预设的代理
行为重新解释为研究发现。完整方法、验证层级和结论规范见
[`methodology.md`](methodology.md)。

## 3. 产品愿景

让使用者能够在封闭环境中提出一个关于市场微观结构或参与者博弈的假设，配置参与者
和市场规则，批量运行可复现实验，并获得能够追溯到订单与决策的证据，而不是只得到
一条看似合理的价格曲线。

## 4. 目标用户

### 4.1 主要用户：个人研究者/开发者

- 希望理解订单簿、价格形成和市场微观结构。
- 能阅读配置、图表及基本统计指标。
- 需要快速编写或调整代理规则并运行对照实验。

### 4.2 次要用户：量化金融学习者

- 希望观察撮合、滑点、库存风险和不同交易行为。
- 需要比历史回测更具互动性的教学环境。

### 4.3 潜在用户：市场监管与风控研究者

- 希望在隔离环境中研究异常交易行为及检测指标。
- 不属于 MVP 的首要交付对象，但产品设计需保留扩展能力。

## 5. 产品目标

- **G-001**：建立正确、确定性的单品种连续竞价与账户系统。
- **G-002**：支持异质散户和多类大资金代理在同一市场中交互。
- **G-003**：使价格、成交、持仓和收益能够追溯到代理观察与决策。
- **G-004**：支持使用固定种子进行批量对照实验和参数扫描。
- **G-005**：通过预先声明的市场统计指标检验模型，而非凭价格图主观判断真实性。
- **G-006**：形成从 PRD、功能规格、代码、测试到实验结论的完整追溯链。

## 6. 非目标

- 不预测任何真实证券、指数或加密资产的未来价格。
- 不连接券商、交易所、钱包或真实资金。
- 不生成自动交易信号或个性化投资建议。
- 不假设存在能够无条件控制价格的单一“庄家”角色。
- MVP 不实现多品种、衍生品、跨市场套利、强化学习或 LLM 代理。
- MVP 不提供生产级高频撮合性能和真实交易所协议兼容性。
- 不把市场操纵实验转化为真实市场中的执行方法。

## 7. 核心概念与角色边界

### 7.1 市场角色

| 角色 | 核心目标 | 典型能力 | 与其他角色的区别 |
|---|---|---|---|
| 散户代理 | 基于有限信息交易 | 资金较小、观察频率不同 | 可采用噪声、趋势、均值回复或羊群规则 |
| 库存型做市商 | 提供流动性并控制库存 | 双边报价、报价偏移 | 收益主要来自点差，不等同于操纵者 |
| 大资金执行者 | 完成目标仓位并降低冲击 | 拆单、执行进度控制 | 目标是成交质量，不必拥有信息优势 |
| 订单流预知者 | 利用提前获知的订单流 | 提前 N 个事件获知大单到达 | 优势来源必须在配置中显式表示 |
| 操纵型代理 | 监管压力测试 | 特殊订单行为 | 不进入 MVP，仅限封闭检测研究 |

模型中不存在外生基本价值，因此"信息优势"不表现为更准确的价值信号，而表现为对
**未来订单流**的提前可见性。该定义在加密市场有现实对应（mempool 可见性、MEV），
且可配置、可测量（见 [ADR-003](../adr/003-crypto-spot-market-without-fundamentals.md)）。

### 7.2 能力维度

任何参与者优势必须由以下可测参数表达：

- 初始现金与持仓；
- 信息质量与信息到达时间；
- 观察频率和通信延迟；
- 可用订单类型及单笔数量限制；
- 风险预算、库存限制和交易成本；
- 对公开订单簿、成交和基本价值的可见范围。

## 8. MVP 用户旅程

### 8.1 创建实验

用户复制基准配置，选择市场规则、代理类型、数量、能力参数、运行时长和随机种子。
系统在运行前完成配置校验，并生成唯一配置摘要。

### 8.2 运行市场

系统按确定性事件顺序推进代理观察、决策、下单、撤单、撮合和账户更新。违反现金、
持仓或市场规则的订单被拒绝并记录原因。

### 8.3 查看结果

运行结束后，用户获得价格、成交量、点差、深度、价格冲击、代理持仓及 PnL 等指标，
并可从成交反查相关订单、代理决策和当时信息集。

### 8.4 比较实验

用户可使用相同外生路径和成组随机种子比较两个场景。系统输出分组统计和差异，而非
只展示单次运行结果。

## 9. MVP 功能范围

### 9.1 市场与撮合

- **PR-001**：提供单品种、价格时间优先的连续竞价限价订单簿，按加密现货制度 24/7
  连续交易，无休市、无集合竞价、无涨跌停、无 T+1、无整手限制。
- **PR-002**：支持限价单、市价单、撤单、部分成交和订单拒绝。
- **PR-003**：支持 tick size（含极细粒度）、最小数量，以及 **maker / taker 分离计费**
  的手续费配置。
- **PR-004**：维护现金、持仓、冻结量、费用和 PnL，保证账本守恒。
- **PR-017**：明确定义退化状态行为——价格下界、代理破产后行为、订单簿单边清空时的
  市价单处理、长时间无成交的判定。允许极端行情发生，但不得产出未定义状态。

### 9.2 参与者

- **PR-005**：提供噪声、趋势、均值回复和羊群型散户代理。均值回复代理锚定内生长周期
  价格统计量，系统中不存在外生基本价值过程。
- **PR-006**：提供库存型做市商、大资金执行者和订单流预知者。
- **PR-007**：允许通过统一配置调整资金、信息、速度和风险能力。
- **PR-008**：代理不得读取超出其信息集的仿真内部状态。

### 9.3 实验与复现

- **PR-009**：实验配置、随机种子和指标定义必须可序列化并随结果保存。
- **PR-010**：相同版本、配置和种子必须产生逐事件一致的结果。
- **PR-011**：支持单命令运行多种子对照实验。
- **PR-012**：每次运行记录代码版本、配置哈希、开始时间和完成状态。

### 9.4 可观察性与分析

- **PR-013**：记录订单、撤单、成交、订单簿、决策和账户事件。**账户快照频率必须可
  配置**，以支撑回放中的持仓与 PnL 演化曲线。
- **PR-014**：输出价格、收益、波动率、点差、深度、成交量和价格冲击。
- **PR-015**：输出各代理及代理类型的收益、回撤、库存和交易成本，**均须按时间序列
  输出而不仅是终值**。
- **PR-016**：支持从成交追溯至代理观察、规则、订单和账户变化。
- **PR-018**：提供单文件 HTML 回放器，以事件日志为唯一输入，逐帧呈现价格走势、订单簿
  与各类代理状态的演化，支持拖拽进度、变速与暂停。仿真内核不得依赖呈现层。
- **PR-019**：输出总结报告。回放视图与总结报告为同一 HTML 产物的两个视图，共享同一
  数据源；同时输出 Markdown 摘要用于版本追溯与实验间比对。

## 10. 关键产品决策

### 10.1 MVP 交互方式与呈现

MVP 采用配置文件加命令行运行方式，结果以机器可读文件（JSONL / Parquet）输出。

可视化实现为**事件日志的回放**而非在线实时渲染：仿真内核只写日志、不感知呈现层，
回放器与报告作为日志的消费者独立交付。离散事件仿真中"实时"不具物理意义——基准
仿真数秒即可跑完，在线实时要么需要人为给内核加延迟（污染性能 KPI 并违反 NFR-004），
要么等价于回放。回放方案另有可复现、可回看、可存档的优势。详见
[ADR-004](../adr/004-replay-based-visualization.md)。

### 10.2 MVP 市场范围

MVP 标的为**加密现货**：24/7 连续交易，无涨跌停、无 T+1、无整手、无集合竞价，
tick 粒度可配置，手续费按 maker / taker 分离计费。该选择用于排除交易制度对价格
路径的干扰，使研究集中于订单流互动本身。

永续合约与资金费率不进入 MVP。A 股及其他股票市场制度（T+1、涨跌停、整手、集合
竞价）作为独立规格评审。交易所层须从第一天起设计为**约束钩子**接口（订单准入校验、
可交易数量计算、价格边界），使这些制度将来能以插件方式接入而非重写撮合核心。

### 10.2.1 极端情况处理

不引入价格限制或熔断，允许崩盘、暴涨与流动性枯竭自由涌现。但退化状态的行为必须
明确定义（PR-017），且须预先声明"发散样本"的判定标准与排除规则并报告排除率——
统计验证在发散样本上不具意义，但排除过程必须透明。

### 10.3 代理实现方式

MVP 使用可解释的规则代理。强化学习代理必须在基准市场完成验证后引入，并与规则代理
使用相同的账户、信息集和订单接口。

### 10.4 数据策略

MVP 使用纯内生订单流，不使用外生基本价值过程，也不依赖受限的历史订单数据。

MVP **不锁定具体币种**：将参数校准到某一具体标的（波动率、tick、费率结构）推迟至
M4 立项，避免在合成订单流阶段过早引入真实数据依赖。后续引入真实数据校准时，必须
记录数据许可、清洗方法和模型适用范围。

### 10.5 时间推进内核

采用**离散事件内核**，不使用固定步长。固定步长会使通信延迟只能量化为步长整数倍，
令 A-003 的"速度"维度失去分辨率。实现须满足三条硬约束：整数逻辑时间戳（禁止浮点）、
事件全序主键 `(timestamp, priority_class, seq)`、每代理独立 RNG 流（按 `agent_id`
派生）。第三条是配对实验成立的前提。详见
[ADR-001](../adr/001-discrete-event-time-kernel.md)。

### 10.6 仿真底座

**自建最小内核**，核心领域层仅使用标准库；ABIDES、PAMS 等框架作为设计参考而非依赖。
宪章第 2 条要求撮合正确性由本项目测试保证，审计外部实现的成本高于自建；且外部框架
的依赖栈与 NFR-004 冲突。详见 [ADR-002](../adr/002-build-minimal-kernel.md)。

## 11. 产品成功指标

### 11.1 工程可信度

- **KPI-001**：撮合、订单优先级、撤单、部分成交及账本守恒验收测试 100% 通过。
- **KPI-002**：固定配置与种子的重复运行产生相同事件摘要哈希。
- **KPI-003**：订单簿与账本核心逻辑分支覆盖率不低于 90%。
- **KPI-004**：基准配置 `benchmarks/BENCH-001.yaml`（固定代理构成、固定事件数、固定
  种子）在指定参考硬件上的单核运行时间不超过 10 秒。性能门槛必须以可执行的基准
  配置表达，而非散文描述，否则无法跨版本回归比较。"事件"与"代理动作"的精确定义
  见指标字典（M0 交付物）。

### 11.2 研究可用性

- **KPI-005**：用户可以用一个命令完成不少于 30 个随机种子的对照实验。
- **KPI-006**：标准结果报告覆盖 PR-014 和 PR-015 的全部指标。
- **KPI-007**：任一成交均可追溯至完整决策和账户链路。
- **KPI-008**：基准验证报告逐项声明市场统计特征为通过、失败或不适用，并报告发散
  样本的判定标准与排除率。
- **KPI-011**：回放器能仅以事件日志为输入还原整段仿真，且回放结果与原运行逐帧一致。

### 11.3 结论质量

- **KPI-009**：所有研究结论注明配置范围、样本量、不确定性及限制。
- **KPI-010**：不存在仅凭单次价格路径得出的产品级结论。

## 12. 市场验证框架

基准模型至少检查以下特征；MVP 不要求全部通过，但必须透明报告：

- 短周期收益分布是否呈现厚尾；
- 收益序列是否缺乏显著线性自相关；
- 绝对收益或平方收益是否呈现波动聚集；
- 成交量与波动率是否表现出合理关系；
- 点差、深度、撤单率和订单大小是否处于稳定范围；
- 不同订单规模的价格冲击是否具有合理的非线性；
- 财富和库存变化能否由交易、费用及价格变化完全解释。

由于模型中不存在外生基本价值（ADR-003），均值回复力由锚定内生长周期价格统计量的
代理提供。该内生锚含自指结构，其稳定性不能假定：**M2 必须通过参数扫描确认价格
不发散的参数区间，并将不稳定区间作为结果报告而非隐藏。**

同时须预先声明**发散样本的判定标准与排除规则**。统计验证在发散样本上不具意义，
但排除过程必须透明，排除率本身即是一项结果（见 methodology §9.2）。

只有基准模型完成验证后，产品才进入策略比较和行为解释阶段。

## 13. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 代理规则预先决定结论 | 形成循环论证 | 消融实验、参数扫描、多种子及失败区域报告 |
| 「价格走势是否影响交易者」被当作研究问题 | 答案已写死在代理规则中，不可证伪 | 改写为占比变化的市场后果类问题（见 §2 与 methodology §11） |
| 内生锚自指导致非预期动力学 | 价格锁定、周期振荡或发散 | M2 参数扫描确认稳定区间，不稳定区间作为结果报告 |
| 去除基本面后有效样本减少 | 统计功效下降 | 预先声明发散样本判定，报告排除率并据此调整样本量 |
| 将做市商与操纵者混淆 | 角色归因错误 | 分离目标函数、能力和行为接口 |
| 模型与真实市场差异过大 | 结论无法外推 | 市场验证、历史数据校准和限制声明 |
| 单次仿真被过度解读 | 偶然路径被视为规律 | 配对随机种子、置信区间和批量实验 |
| 功能过早复杂化 | 难以验证核心正确性 | 单品种、规则代理、CLI 优先 |
| MVP 代理类型过多拖慢核心验证 | M1/M2 交付周期失控 | M2 收敛至四类代理，能力异质性代理后移至 M3（见 §14） |
| 异常行为研究被误用 | 合规与伦理风险 | 仅限封闭仿真、检测导向、禁止实盘接口 |

- 研究技术交易者占比变化对市场质量的影响（§2 第三问）。

**退出条件**：KPI-005、KPI-006、KPI-008 至 KPI-010 达标。

### M4：扩展评审

- A 股及其他股票市场交易制度（通过约束钩子接入）；

- 永续合约与资金费率；
- 历史订单流校准；
- 强化学习代理（若需复用外部框架的训练环境，此时重新评估 ADR-002）；
- 异常交易检测和监管压力测试；
- 多品种或多市场。
