# 代理策略合同：从信息集到订单意图

**适用范围**：跨规格实现合同（当前交付规格 002）  
**状态**：Stable（变更须记 ADR 并评估既有实验可比性）  
**创建日期**：2026-08-01  
**支撑需求**：002 / FR-009—FR-013；PRD / PR-008—PR-011  
**关联**：[事件 Schema](event-schema.md)、[退化状态](degenerate-states.md)、
[指标字典](../product/metrics-dictionary.md)

## 0. 本文为什么必须存在

002 规格定义了因子库与加权信号（P-1），但没有定义**信号如何变成订单**。这中间的
每一个选择——因子如何标准化、历史不足时取什么值、信号如何映射到方向与数量、挂单
挂在哪个价位、旧单撤不撤——都会直接决定厚尾、波动聚集、因子收益与崩盘频率。

**不把它们定死，实验结论就只是实现者选择的结果。** 本文把整条管线写成确定函数：

```text
information_set
  → raw factors          §2
  → normalized factors   §3
  → belief signal        §4
  → target position      §5
  → order intents        §6
  → admission            §7
```

同一信息集 + 同一 RNG 状态**必然**产生同一组订单意图。任何实现自由度都是缺陷。

## 1. 信息集边界

`AGENT_OBSERVE` 事件确定该代理本次可见的内容（事件 Schema §4.4），**只含**：

| 内容 | 说明 |
|---|---|
| 盘口 | `best_bid`、`best_ask`、买卖各 k 档深度（`k = 10 tick`） |
| 成交增量 | **上次观察以来的全部成交**（价、量、主动方向），非仅最后一笔 |
| **已完成**的 K 线序列 | 只到上一根完整 K 线（`bar_ns = 60 秒`，指标字典 §1.9） |
| 自身账户 | 钱包、仓位、开仓成本、保证金占用、保证金率、未成交挂单 |

**当前尚未完成的 K 线不可见**——这是本模型选择不提供的当期信息，不是「前视偏差」
（代理看的仍是过去的数据）。若提供，代理就能对本根内已发生的价格变动抢先反应，
从而凭空增强动量效应，而动量恰好是被检验的因子之一（002 / P-1）。该选择是模型
假设，须在报告中声明。

代理**不可见**：其他代理的身份、持仓、信念权重、未来订单流（订单流预知者后移至
M4），以及全局撮合中间态（A-002）。

## 2. 原始因子

全部在**已完成 K 线**与当前盘口上计算。记 `C[-1]` 为最近一根完整 K 线的收盘价。

| 因子 | 公式 | 所需历史 |
|---|---|---|
| `momentum` | `ln(C[-1] / C[-1-N])` | N+1 根 K 线 |
| `reversion` | `(anchor − last) / last` | 无（锚随成交更新） |
| `herding` | `(主动买量 − 主动卖量) / 总成交量`，最近 W 根 K 线 | W 根 K 线 |
| `book` | `(bid_depth_k − ask_depth_k) / (bid_depth_k + ask_depth_k)` | 无 |
| `noise` | 每次决策独立抽取的标准正态 | 无 |

`anchor` 为该代理自己的内生 EWMA：对**上次观察以来的每一笔成交**按
`anchor ← α·price + (1−α)·anchor` 顺序更新，`α = 1 − 2^(−1/τ)`，τ 以成交笔数计
（指标字典 §1.5）。锚是**逐代理**状态，半衰期各异，不是全局量。

**行情通道是增量事件流，不是快照。** 观察频率低的代理会在一次观察中一次性消化多笔
成交，而不是只看最后一笔——否则锚的差异会同时混入漏采样效应，`τ` 的语义（以成交
笔数计的半衰期）也不再成立。

## 3. 缺失值与冷启动

### 3.1 缺失一律取 0，不取 NaN、不跳过

| 情形 | 取值 |
|---|---|
| K 线不足 `N+1` 根 | `momentum = 0` |
| K 线不足 `W` 根 | `herding = 0` |
| 窗口内总成交量为 0 | `herding = 0` |
| 尚无成交（`last` 未定义） | `reversion = 0`，且 `anchor` 保持初值 `initial_price` |
| 两侧簿皆空 | `book = 0` |
| **单边簿**（一侧深度为 0） | `book = ±1`（满偏），**不是缺失** |

取 0 表示「该因子此刻无信号」，代理不因它下单；取 NaN 会污染加权求和，跳过则会
悄悄改变权重归一化的分母，使同一 `w` 在不同时刻含义不同。

单边簿给满偏是刻意的：一侧无挂单是**极端失衡的真实信息**，不是数据缺失。这也让
`book` 因子在流动性枯竭时给出最强信号，与退化状态 §1.2 的语义一致。

### 3.2 冷启动：唯一的启动规则

订单簿初始为空，因此 `mid`、`last`、`mark` 全部未定义。**若严格执行「盘口不可用则
不下单」，市场永远开不了张**：无挂单 → 无成交 → 无 `mark` → 所有代理跳过决策。

启动规则（**唯一，不得有第二种实现**）：

1. **`mark` 的启动回退**：首笔成交前，`mark` 取配置的 `initial_price`。首笔成交
   产生后**永久停用**该回退，此后 `mark` 恒取最近成交价（§3.3）；
2. **做市商是唯一的启动者**：首笔成交前，做市商以 `initial_price` 为参考价挂出
   双边报价（`initial_price ∓ half_spread`），仓位为 0 故 `skew = 0`，报价完全
   确定；
3. **信念代理在盘口出现后才下单**：做市商挂单后盘口即可用，`book` 与 `noise` 因子
   有值，信念代理正常参与。它们**不使用** `initial_price` 回退——那会让它们在无任何
   市场信息时凭空定价。

由此，事件顺序是确定的：做市商首次观察 → 双边挂单 → 盘口出现 → 信念代理跟进 →
首笔成交 → `mark` 切换到成交价。

**验收示例**：「空市场启动至首笔成交」须作为 M1 的验收用例，断言事件序列与上述一致。

### 3.3 mark 的定义（与保证金检查的触发链一致）

**强平判定所用的 `mark` 取最近成交价 `last`，不取 `mid`。**

理由：`mid` 会随挂单与撤单变动，而本合同 §6.2 规定每次决策全撤重报——若用 `mid`，
一次报价就可能移动 `mark` 并触发强平，在薄簿中甚至可制造「报价触发的强平连锁」。
那不是市场机制，是实现产物。

因此：

- **只有 `TRADE_SETTLE` 能改变 `mark`**，从而只有成交能触发保证金扫描；
- 报价与撤单**不得**仅凭移动中间价触发强平；
- `MARGIN_CALL.caused_by_event_id` 恒指向 `TRADE_SETTLE`（事件 Schema §4.2.2），
  触发链闭合。

指标字典 §3.1 定义了**两个不可混用的 mark**：

| 口径 | 取值 | 用途 |
|---|---|---|
| `risk_mark` | 恒为 `last`（首笔成交前为 `initial_price`） | 保证金与强平判定 |
| `valuation_mark` | `mid`，缺失时退化为 `last` | 权益、未实现 PnL、会计桥接 |

估值用 `mid` 的额外理由：若估值也用 `last`，则成交后 `valuation_mark` 必等于成交价，
会使会计桥接的 `Spread` 与 `Impact` **恒相互抵消**，两个指标同时失去意义
（指标字典 §5.2.1）。

**代理策略中的 `mark`（§5 目标仓位）取 `valuation_mark`**——代理评估自身权益时用的
是公允价，与交易所的风险判定口径无关。

### 3.4 burn-in

冷启动期定义为**前 `max(N_max + 1, W_max)` 根 K 线**（当前配置 61 根 = 3660 秒
逻辑时间）。该期间数据**必须从统计检验中剔除**，作为 burn-in 记入运行元数据。

**研究运行的最低长度须为 `burn_in + 至少 2000 个有效分析采样点`**，即当前配置下
至少 `3660 + 2000 = 5660` 秒逻辑时间。此前指标字典只要求 2000 个采样点，**比 burn-in
本身还短**，运行可能在冷启动尚未结束时就满足终止条件。

运行元数据须分别记录：总采样点数、burn-in 剔除数、有效分析点数。

## 4. 标准化与信念信号

### 4.1 固定尺度截断，不用滚动标准化

各因子量纲不同（`momentum` 是对数收益，`book` 已在 `[−1,1]`），必须先归一：

```text
normalized_i = clip(raw_i / scale_i, −1, +1)
```

| 因子 | `scale` | 依据 |
|---|---|---|
| `momentum` | `"0.01"` | 1% 对数收益视为满信号 |
| `reversion` | `"0.02"` | 2% 偏离视为满信号 |
| `herding` | `"1.0"` | 原始值已在 `[−1,1]` |
| `book` | `"1.0"` | 同上 |
| `noise` | `"1.0"` | 标准正态截断至 `±1` |

**明确排除滚动 z-score 标准化。** 两条理由：一是它需要滚动窗口的均值与标准差，引入
额外的历史依赖与冷启动问题；二是**崩盘时标准差爆炸会把信号压缩到接近 0**——恰好在
最需要反应的时刻使所有代理失灵，这会人为地抑制杠杆连锁，而连锁正是旗舰问题的研究
对象。固定尺度虽然粗糙，但行为可预测，且不随市场状态自适应。

### 4.2 信念信号

```text
signal = Σ wᵢ · normalizedᵢ        权重满足 Σ|wᵢ| = 1，故 signal ∈ [−1, +1]
```

`w` 在运行开始时从 Dirichlet 分布抽取后**固定不变**（002 / D-3、FR-009）。抽取后
按 `Σ|wᵢ| = 1` 归一化。

## 5. 目标仓位

信号解释为**目标仓位占最大可承受仓位的比例**：

```text
max_notional    = equity × 10000 / initial_bp           # initial_bp = 10000 / leverage_tier
max_position    = floor(max_notional / mark)            # 单位：min_quantity 整数
target_position = trunc(signal_bp × max_position / 10000)   # 向零取整
```

- `initial_bp` 由该代理抽到的 `leverage_tier`（1x / 3x / 10x）决定，与账户合同
  §3.3 的开仓准入使用同一口径——策略层的目标仓位与准入层的检查必须一致，否则代理会
  持续产生注定被拒的意图；
- `signal = +1` → 满多头，`−1` → 满空头，`0` → 空仓；
- `equity` 与 `mark` 取本次观察时刻的值，`mark` 为 `valuation_mark`（§3.3）；
  两侧簿皆空且无成交时 `valuation_mark` 未定义，**跳过本次决策**，不下单。

这一步是整条管线中经济含义最强的一处：它使**杠杆档位直接放大信号的仓位后果**，
从而让「初始杠杆分布是否足以产生连锁」成为可测量的问题（旗舰问题）。

## 6. 订单意图

```text
delta = target_position − current_position
```

- `|delta| < min_quantity` → **不下单**（避免无意义的碎单）；
- `delta > 0` → 买入 `delta`；`delta < 0` → 卖出 `|delta|`；
- 单笔数量上限 `max_order_qty`，超出则**只下上限那一笔**，剩余部分留待下次决策——
  不自动拆单（拆单是大资金执行者的能力，后移至 M4）。

### 6.1 挂单价格与激进度

一律使用**限价单**。价格由逐代理抽取的 `aggressiveness ∈ [0, 1]` 决定：

```text
买单价 = best_bid + aggressiveness × (best_ask − best_bid)
卖单价 = best_ask − aggressiveness × (best_ask − best_bid)
```

- `aggressiveness = 0` → 挂在同侧最优价，**必为 maker**；
- `aggressiveness = 1` → 挂到对侧最优价，**立即成交，必为 taker**；
- 中间值 → 挂在价差内部，改善盘口。

**maker / taker 的分化由此自然产生**，不需要单独的「代理类型」。这也使 maker 返佣与
taker 费率的不对称（ADR-005 §3）能真实影响不同代理的收益。

`aggressiveness` 在运行开始时抽取并固定，它是代理的**执行能力维度**（A-003）。

盘口不可用时的退化：
- 单边簿——缺失一侧用 `last ± spread_fallback`（配置项）替代；
- 两侧皆空——跳过本次决策，不下单。

### 6.2 撤单：全撤重报

**每次决策先撤销自己全部未成交挂单，再按上述规则重新下单。**

理由是确定性与无状态：保留旧单需要判断「旧单是否仍然有效」，而该判断本身又是一组
自由度（价格偏离多少算失效？挂了多久算过期？）。全撤重报没有这些自由度。

代价是撤单率偏高，且每次决策都产生撤单事件。这一点已知并接受：撤单率是被观测的指标
（指标字典 §3.3），报告须声明它受本规则影响，**不得解读为代理的策略特征**。

## 7. 准入与对齐

订单在提交前按顺序检查，**任一不通过即丢弃该意图，不重试、不降级**：

1. **tick 对齐**：买单价格向下取整、卖单价格向上取整至 tick 整数倍——朝**不利于自己
   成交**的方向取整，避免取整意外制造更激进的报价；
2. **数量对齐**：向下取整至 `min_quantity` 整数倍；取整后为 0 则丢弃；
3. **初始保证金检查**：按账户合同 §3.3 计算，所需初始保证金超过可用则拒绝。
   减仓单跳过该检查——否则账户会被锁死在无法自救的状态；
4. **预冻结**：按 ADR-005 §4 冻结**初始保证金**与手续费上界（不是名义金额）。

被拒绝的意图仍写入 `ORDER_ARRIVAL` 事件（`accepted = false` 与 `reject_reason`），
因为「代理想做什么」与「交易所允许什么」的差异本身是研究数据。

## 8. 做市商：唯一的例外

库存型做市商**不使用信念信号**（§2—§6 不适用），行为独立定义：

```text
skew  = inventory_skew_k × (current_position / max_inventory)     ∈ [−1, 1]
bid   = mid − half_spread − skew × half_spread
ask   = mid + half_spread − skew × half_spread
```

- 双边各挂 `quote_size`，每次决策全撤重报（§6.2 同样适用）；
- `skew > 0`（持仓偏多）时整体报价下移，**更容易被买走、更难买入**，从而回归中性；
- 库存达 `max_inventory` 时停止该方向的报价；
- 保证金率低于维持线时停止双边报价，只挂减仓方向。

**与信念代理共享**：§1 信息集边界、§6.2 撤单规则、§7 准入与对齐、保证金与强平。
**不共享**：因子、信号、目标仓位映射。

做市商是市场里唯一的持续流动性提供者，其参数（`half_spread`、`max_inventory`、
`inventory_skew_k`）直接决定簿的厚度，因而**必须作为杠杆连锁实验的敏感性维度**——
做市商越薄，同样的强平量造成的价格滑落越深（002 / A-005）。

## 9. 数值确定性

策略计算含 `ln`、`2^(−1/τ)`、标准正态抽样与乘除，这些都会改变最终的 tick 与数量。
必须冻结：

| 项 | 规则 |
|---|---|
| 中间精度 | 因子与信号计算统一用 `Decimal`，精度 28 位有效数字 |
| 信号量化 | `signal` 量化为 `[−10000, +10000]` 的**整数万分数**后再参与目标仓位计算 |
| 平局舍入 | 一律 `ROUND_HALF_EVEN`（银行家舍入），**不用** `ROUND_HALF_UP` |
| 目标仓位 | `round()` 改为向零取整（`ROUND_DOWN`），避免边界上多开仓 |
| 标准正态 | 固定用 **Marsaglia polar**（§10.3），不用 `random.gauss` 的平台实现 |
| `ln` / `2^x` | 用 `Decimal.ln()` / `Decimal.exp()`，不用 `math` 模块的浮点版本 |

**跨进程测试**：对恰好位于半 tick、半数量单位、信号阈值 `±10000` 边界的案例，
须断言两个独立进程得到逐位相同的结果。

## 10. 随机数：纯标准库的确定性合同

### 10.1 语义键 → 随机比特

**不使用 `numpy.random.SeedSequence`** —— NumPy 不是标准库，与 KR-005「核心领域层
仅使用 Python 标准库」冲突。改用 `hashlib.blake2b`（标准库，规范固定，跨版本稳定）：

**长度前缀编码**，不用分隔符拼接：

```text
def encode(field: str) -> bytes:
    b = field.encode("utf-8")
    return len(b).to_bytes(2, "big") + b        # 2 字节大端长度 + 内容

key_bytes = encode(str(master_seed)) + encode(str(agent_id)) + encode(mechanism)           + encode(str(decision_index)) + encode(str(draw_index))
bits      = blake2b(key_bytes, digest_size=8).digest()        # 64 bit
```

**分隔符拼接会产生键碰撞**：`agent_id="x|y", mechanism="noise"` 与
`agent_id="x", mechanism="y|noise"` 在 `|` 拼接下得到同一个键，两个不同的随机流会
完全重合。已验证长度前缀编码不存在该碰撞。

各整数字段以十进制无前导零书写，UTF-8 编码。编码规则**是规范的一部分**，任何改动
都会改变全部随机流。

`mechanism` 取值：`belief_weights`、`half_life`、`aggressiveness`、`leverage_tier`、
`momentum_lookback`、`herding_window`（**建仓期一次性抽取**，`decision_index = 0`），
以及 `noise_factor`（**每次决策抽取**，`decision_index` 为该代理的决策序号）。

### 10.2 比特 → 开区间均匀数

```text
v = int.from_bytes(bits, "big") >> 11          # 取高 53 位
u = (Decimal(v) + 1) / (Decimal(2**53) + 1)    # 严格落在 (0, 1)
```

**必须是开区间**：`u = 0` 会使 `ln(u)` 发散，`u = 1` 会使部分变换退化。

### 10.3 均匀数 → 各分布

| 分布 | 算法 | 用途 |
|---|---|---|
| 标准正态 | **Marsaglia polar**（拒绝采样，不用三角函数） | `noise` 因子 |
| 对数正态 | `exp(μ + σ·z)`，`z` 由上行得到 | 半衰期 τ |
| Gamma(α,1) | **Marsaglia–Tsang**，见 §10.3.1 | Dirichlet 的分量 |
| Dirichlet | `xᵢ = Gamma(αᵢ,1)`，再按 `Σx` 归一；见 §10.3.2 | 信念权重 |
| 均匀 `[a,b]` | `a + u × (b − a)` | `aggressiveness` |
| 离散分布 | 按万分数累积区间查找，`u × 10000` 落入哪段 | `leverage_tier` |

#### 10.3.1 Gamma(α, 1)：Marsaglia–Tsang

```text
若 α < 1:  返回 Gamma(α+1, 1) × u^(1/α)     # u 为一个新的开区间均匀数
否则:
    d = α − 1/3
    c = 1 / sqrt(9d)
    循环:
        z = 标准正态（Marsaglia polar，消耗 2 个 draw）
        v = (1 + c×z)^3
        若 v ≤ 0: 继续下一轮
        u = 开区间均匀数（消耗 1 个 draw）
        若 ln(u) < 0.5×z² + d − d×v + d×ln(v):  返回 d×v
        否则继续
```

`u^(1/α)` 用 `Decimal` 实现为 `(u.ln() / α).exp()`，精度 28 位（§9）。

#### 10.3.2 Dirichlet 的 draw-index 分配

各分量使用**独立的 mechanism 名**，避免共享计数器：

```text
xᵢ = Gamma(αᵢ, 1)   使用 mechanism = f"belief_weights_{i}"，i 从 0 开始
w  = x / Σx
```

这样任一分量的拒绝次数不会影响其他分量的随机流——若共用一个 mechanism 并顺序推进
`draw_index`，某个分量多拒绝一次就会让后续所有分量错位。

#### 10.3.3 拒绝采样的 draw_index 规则

- **Marsaglia polar**：每轮消耗 2 个 `draw_index`，拒绝则 `+2` 继续，**不重置**；
- **Marsaglia–Tsang**：每轮消耗 2（正态）+ 1（均匀）= 3 个，拒绝则 `+3` 继续；
- 递归调用（`α < 1` 分支）从当前 `draw_index` 继续，不另起计数。

消耗量随拒绝次数变化，但对给定语义键**完全确定**。

`ln` 与 `sqrt` 一律用 `Decimal.ln()` / `Decimal.sqrt()`，精度 28 位（§9），
**不用 `math` 模块**——后者是平台浮点，跨平台可能差最后一位。

### 10.4 为什么按语义键而非调用顺序

配对对照中，两组的行为会因处理变量而分叉，调用顺序随之错位。语义键使「同一代理在
同一决策序号上的 `noise`」在两组中保持一致，与行为是否分叉无关（002 / KR-004）。
这是配对实验效力的前提——否则「相同种子」只保证可复现，不保证可配对。

已验证：同一语义键重复调用结果一致；不同 `agent_id` 或 `mechanism` 互不干扰。

## 11. 挂单保证金占用与自成交

### 11.1 占用算法：按最坏情形合并计算

**不逐单累加占用**——那会在同向多单时重复占用、在反向单时低估占用。正确做法是按
「当前仓位 + 所有活动挂单若全部成交」的两个极端计算：

```text
buy_all  = position + Σ(所有活动买单数量)
sell_all = position − Σ(所有活动卖单数量)
worst_notional = max(|buy_all|, |sell_all|) × valuation_mark
required_reserved = ceil(worst_notional × initial_bp / 10000)
```

`reserved_units` **恒等于**该值，每次挂单、撤单、部分成交后**整体重算**，不做增量
加减——增量维护极易在部分成交与撤单交错时漂移。

同向多单只放大一侧的极端值，反向单会同时抬高两个极端中的一个，两种情形都被自然
覆盖。

### 11.2 禁止自成交

**同一代理的买单与卖单不得相互成交。** 撮合时若发现对手方 `agent_id` 与自己相同，
执行 **cancel-resting**（撤销簿上那张较早的挂单，让新单继续撮合下一档）。

选 cancel-resting 而非 cancel-newest 或 cancel-both 的理由：本合同 §6.2 规定每次
决策全撤重报，簿上的旧单已经是过时意图，撤掉它符合代理的实际意愿；撤新单会使本次
决策完全失效。

被撤销的挂单写入 `ORDER_ARRIVAL`（`action = CANCEL`，`reject_reason =
SELF_TRADE_PREVENTION`），使其可被审计——自成交阻止的发生频率本身是一项观测量。

允许自成交则须定义两条分录的应用顺序与费用结果（同一账户既付 taker 费又收 maker
返佣），复杂度与研究价值不成比例，故排除。

## 12. 本合同的已知局限

以下几点是**刻意的简化**，不是遗漏。它们都会影响结论，因此必须在报告中声明：

| 简化 | 影响 | 何时重新评估 |
|---|---|---|
| 固定尺度而非自适应标准化 | 极端行情下信号饱和，代理反应「钝化」 | M3 稳健性检验 |
| 全撤重报 | 撤单率偏高，簿的瞬时深度波动被放大 | 若撤单率显著影响深度指标 |
| 目标仓位线性映射信号 | 排除了阈值型、金字塔加仓等真实行为 | M3 替代行为映射 |
| 不自动拆单 | 大额调仓一次性冲击簿 | 大资金执行者引入时（M4） |
| 永续资金费为 0 | 长时间持仓无成本，永续价格不锚定任何外部参照 | 实验时长显著延长时 |

**M3 的稳健性检验必须至少替换其中一项**（PRD §15），以确认旗舰结论不依赖单一行为
映射——报告已指出，只在单一映射下成立的结论是实现的性质，不是市场的性质。
