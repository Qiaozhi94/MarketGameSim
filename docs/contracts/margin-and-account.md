# 账户与保证金合同（线性永续合约）

**适用范围**：跨规格实现合同（当前交付规格 002）  
**状态**：Stable（变更须记 ADR 并评估既有实验可比性）  
**创建日期**：2026-08-01  
**支撑需求**：002 / FR-004—FR-008；PRD / PR-004—PR-007  
**关联**：[事件 Schema](event-schema.md)、[退化状态](degenerate-states.md)、
[代理策略](agent-strategy.md)、[指标字典](../product/metrics-dictionary.md)、

## 0. 为什么是永续合约

此前文档语义混合：制度名为 `crypto_perp_free`（永续），账本却按现金与库存交割
（现货），退化状态要求「现金不得为负」，而预冻结规则要求冻结**全额**名义金额——
那样根本无法杠杆买入。本文选定**线性永续合约**并消除该矛盾。

选它而非杠杆现货的理由：

| 性质 | 永续 | 杠杆现货 |
|---|---|---|
| 净持仓 | **恒为 0**（每笔成交产生一多一空） | 非零，随初始配置而定 |
| 权益守恒 | **精确成立**（见 §2.3） | 不成立，需 mark-to-market 桥接 |
| 做空 | 天然支持，与做多对称 | 需融券、券源与费用 |
| 债务/利息/借贷分录 | 不需要 | 必须定义 |
| 与旗舰问题的对应 | 真实的爆仓潮就发生在永续市场 | 融资盘平仓，但需股票式制度 |

代价：须定义资金费率（**第一版设 0**，见 §6），且初始仓位必须为 0（§7）。

## 1. 账户字段

全部为最小单位整数（ADR-005 §1）：

| 字段 | 含义 | 符号约定 |
|---|---|---|
| `wallet_units` | 钱包余额（保证金本金） | 正常为正；穿仓瞬间可为负，随即核销（§5） |
| `position_units` | 合约仓位 | 多头为正，空头为负 |
| `entry_notional_units` | 开仓成本累计 | 多头为正，空头为负（§2.1） |
| `reserved_units` | 挂单占用的保证金 | 非负 |
| `realized_pnl_units` | 已实现盈亏累计 | 有符号 |

**没有「库存」，也没有负现金表达融资。** 杠杆通过「仓位名义价值 > 钱包余额」体现，
不通过借款体现。

## 2. 核心量

### 2.1 开仓成本与已实现盈亏

`entry_notional` 随成交按**同向加仓 / 反向平仓**两种情形更新：

```text
同向（sign(pos) == sign(Δpos) 或 pos == 0）：
    entry_notional += Δpos × price          # Δpos 有符号
    realized_pnl   += 0

反向（平掉部分或全部）：
    closed          = min(|Δpos|, |pos|)                    # 本次平掉的数量
    avg_entry       = entry_notional / pos                  # 有符号相除，得正的均价
    realized_pnl   += closed × (price − avg_entry) × sign(pos)
    entry_notional -= closed × avg_entry × sign(pos)
    若反向超出（翻转方向）：剩余部分按同向规则建新仓
```

`avg_entry` 的除法**是整个系统中唯一的非精确除法**。舍入规则：向零取整
（`int(a/b)` 语义），余数留在 `entry_notional` 中，随后续平仓自然消化。该余数不影响
守恒——`wallet` 与 `realized_pnl` 的变动始终由实际成交金额决定，`entry_notional` 只
用于计算未实现盈亏。

### 2.2 未实现盈亏与权益

```text
unrealized_pnl = position_units × mark − entry_notional_units
equity         = wallet_units + unrealized_pnl
```

### 2.3 守恒性质（替代原 C1/C2）

永续下的两条守恒等式：

```text
[C1] 钱包守恒
Σ wallet_units(t) + 交易所费用_units(t) + 交易所风险账户_units(t)
    = Σ wallet_units(0)

[C2] 仓位守恒
Σ position_units(t) = 0        （恒等式，非「等于初值」）
Σ entry_notional_units(t) = 0
```

**C2 使权益守恒重新精确成立**，无需 mark-to-market 桥接：

```text
Σ unrealized_pnl = mark × Σ position − Σ entry_notional = 0 − 0 = 0
∴ Σ equity = Σ wallet = 常数（与 mark 无关）
```

已验算：三代理场景下 `mark` 取 100 / 120 / 50，`Σ权益` 恒为 30000，个体权益此消彼长。
这是永续相对杠杆现货的核心优势——上一版「权益不是守恒量」的整个麻烦在此消失。

指标字典 §5.1 的 mark-to-market 桥接式仍然有效，但降级为**个体账户**的检验，不再是
全局对账的必需品。

## 3. 保证金

### 3.1 三条比例线

全部以**整数万分数**表达（指标字典 §4.1），避免浮点比较决定强平与否。

| 名称 | 符号 | BENCH-001 取值 | 用途 |
|---|---|---|---|
| 初始保证金率 | `initial_bp` | 由杠杆档位定：`10000 / leverage_tier` | 开仓准入 |
| 维持保证金率 | `maint_bp` | 500（5%） | 强平触发 |
| 目标恢复率 | `target_bp` | 1000（10%） | 强平数量计算 |

**注意口径变更**：此前文档用「担保比例 105% / 110%」（权益/保证金占用），本文改用
**保证金率**（保证金/名义价值），两者互为倒数关系。改用保证金率的理由是它在 1x 与
空仓时不退化——权益/保证金占用在无仓位时分母为 0。

对应关系：维持保证金率 5% ≈ 原担保比例 105% 的同一杠杆水平。

### 3.2 保证金占用与保证金率

```text
notional_units   = |position_units| × mark                    # 恒非负
margin_used      = notional_units × maint_bp / 10000          # 维持保证金
margin_ratio_bp  = equity × 10000 / notional_units            # 当前保证金率
```

**边界行为**：

- `position == 0` → `notional == 0` → **`margin_ratio_bp` 未定义**，记为 `null`，
  账户**永不触发强平**（无仓位无风险）。这消除了 1x 账户与空仓账户的分母退化；
- `equity ≤ 0` → `margin_ratio_bp ≤ 0`，立即触发强平并大概率穿仓（§5）；
- 多头与空头**完全对称**：`notional` 取绝对值，空头保证金率的计算与多头一致。

### 3.3 开仓准入（初始保证金）

准入检查**独立于维持保证金**，且更严格：

```text
新仓位 = position + Δpos（本单若全部成交）
新名义 = |新仓位| × price
所需初始保证金 = 新名义 × initial_bp / 10000
可用 = equity − reserved_units

拒绝条件：所需初始保证金 > 可用
```

- **减仓单永不因保证金被拒**（`|新仓位| < |position|` 时跳过该检查）——否则账户
  会被锁死在无法自救的状态；
- 挂单按**最坏情形**占用 `reserved_units`（假设全部成交），撤单或成交时释放；
- 该检查取代了 ADR-005 §4 的「冻结全额名义金额」——那是现货语义，永续下只冻结
  保证金。**ADR-005 §4 须同步修订**。

## 4. 强平

### 4.1 触发

```text
margin_ratio_bp < maint_bp  且  position != 0   →  待强平
```

**恰好等于维持线不触发**（闭区间安全侧，与退化状态 §5 一致）。

### 4.2 强平数量

平掉最小数量，使保证金率恢复到 `target_bp`。设平掉 `q`（`0 < q ≤ |position|`）：

```text
平仓后名义 = (|position| − q) × mark
平仓后权益 ≈ equity − q × mark × taker_bps / 10000        # 仅扣手续费
要求：平仓后权益 × 10000 ≥ 平仓后名义 × target_bp

解得（忽略手续费的一阶近似，实现须用整数二分求最小可行 q）：
q ≥ |position| − equity × 10000 / (mark × target_bp)
```

**实现规则**：以 `min_quantity` 为步长，用整数二分求满足条件的**最小** `q`，
**向上取整**至步长整数倍。若 `q ≥ |position|` 则全平。

`required_quantity_units` 即该 `q`，写入 `MARGIN_CALL` 事件（事件 Schema §4.2.2）。

### 4.3 部分成交后重新计算

强平单部分成交后，**不沿用原 `q` 的剩余部分**，而是按新的账户状态**重新计算**
`required_quantity_units`——价格已经移动，原数量不再对应 `target_bp`。

每次重算产生一个新的 `MARGIN_CALL` 事件，`chain_depth` 继承自触发它的那次判定。

## 5. 穿仓与核销

### 5.1 两步分录

穿仓（`equity < 0`）的处理分两步，**不得合并**：

```text
步骤 1：确认（MARGIN_CALL，verdict = BREACHED）
    仓位已全平，wallet_units 为负，记为 W < 0
    此时 C1 仍然成立（负钱包也是钱包）

步骤 2：核销（同一事件的账户分录）
    wallet_units            : W → 0
    exchange_risk_pnl_units : R → R + W        # W 为负，风险账户减少
    账户状态转入 LIQUIDATED
```

### 5.2 风险账户是有符号量，损失记负数

**这是上一版的符号错误**：此前 `negative_equity_units` 定义为正的穿仓损失，而 C1
将风险账户相加——核销时代理钱包 −102.45 → 0（+102.45），风险账户 0 → +102.45
（再 +102.45），C1 左侧凭空多出 **204.90**。

正确定义：字段名为 **`exchange_risk_pnl_units`**，**有符号，交易所承担的损失记
负数**。核销时 `Δwallet = +102.45`、`Δrisk = −102.45`，合计 0，C1 守恒。已验算。

事件 Schema 中的 `negative_equity_units` 字段**须重命名为 `risk_pnl_delta_units`**
并改为有符号。

### 5.3 代理侧的 PnL 归属

被核销的损失计入该代理的 `FundingAndDefault` 项（指标字典 §5.2），**时点为核销事件，
符号为负**（代理免除了这部分损失，但它已经体现为权益归零）。核销后代理权益恒为 0，
不再参与后续统计的活跃账户集合。

## 6. 资金费率

**第一版 `funding_rate_bp = 0`，机制预留但不启用。**

启用后的语义：每 `funding_interval_ns` 按 `position × mark × funding_rate_bp / 10000`
在多空之间转移，多头付空头（费率为正时）。因为 `Σ position = 0`，该转移**自动零和**，
不影响 C1。

第一版设 0 的理由：资金费率是使永续价格锚定现货的机制，而本模型**没有现货参照**
（D-4 无外生基本价值），费率无从确定。强行引入一个人造费率会成为未声明的处理变量。

## 7. 初始仓位必须为 0

所有账户以 `position = 0`、`entry_notional = 0` 开始，只有 `wallet_units` 为正。

理由是 C2 的恒等式：`Σ position ≡ 0` 要求任何非零初始仓位都必须有对手方。给所有代理
配置相同的正初始仓位（旧 BENCH-001 的做法）**在永续下根本不合法**。

由此，**「初始杠杆分布」这一表述不再成立**（P1-R02）：配置抽取的是
`leverage_tier`，即该代理的**杠杆上限**；实际杠杆由代理自己建仓产生，是内生结果而非
初始条件。旗舰问题、A-005 与报告措辞须统一改为「**杠杆上限分布及其内生建仓后果**」。

## 8. 手工验算示例

### 示例 1：多头开仓

`wallet = 10000`，`position = 0`，`mark = 100`，`leverage_tier = 3`（`initial_bp = 3333`）。
买入 50 单位 @ 100，taker 费率 5 bps。

```text
名义 = 50 × 100 = 5000
所需初始保证金 = 5000 × 3333 / 10000 = 1666.5 → 1666（向下取整对代理不利，故用 1667）
可用 = equity − reserved = 10000 − 0 = 10000 ≥ 1667      ✓ 准入通过

成交后：
  fee            = 5000 × 5 / 10000 = 2.5
  wallet         = 10000 − 2.5 = 9997.5      # 注意：不扣名义金额，只扣手续费
  position       = +50
  entry_notional = +5000
  unrealized     = 50 × 100 − 5000 = 0
  equity         = 9997.5
  notional       = 5000
  margin_ratio   = 9997.5 × 10000 / 5000 = 19995 bp（199.95%）  ≫ maint 500 ✓
```

**关键**：永续开仓**不扣除名义金额**，只扣手续费——这正是杠杆的来源。

### 示例 2：价格下跌触发强平

承示例 1，`mark` 跌至 82。

```text
unrealized   = 50 × 82 − 5000 = −900
equity       = 9997.5 − 900 = 9097.5
notional     = 50 × 82 = 4100
margin_ratio = 9097.5 × 10000 / 4100 = 22189 bp    仍远高于 500，不触发
```

改设该代理满杠杆重仓：`wallet = 1000`，`position = +500`，`entry_notional = 50000`
（均价 100）。

先反解触发点，`equity × 10000 = notional × maint_bp`：

```text
(1000 + 500×mark − 50000) × 10000 = 500×mark × 500
5,000,000×mark − 490,000,000 = 250,000×mark
mark = 490,000,000 / 4,750,000 ≈ 103.16
```

**触发点高于开仓价 100** —— 也就是说，这个仓位**在建仓那一刻就已经低于维持线**，
根本开不出来：50,000 名义价值对 1,000 钱包是 50x 杠杆，而 `leverage_tier` 上限只有
10x，§3.3 的初始保证金检查会直接拒绝。

这个「算错的例子」有保留价值，它示范了两件事：**初始保证金检查是防止此类仓位存在的
第一道闸**；以及**反解触发点必须实算**，凭直觉写「跌 0.5% 触发」会得到错误结论。

改用一个合法的 10x 仓位：`wallet = 5000`，`position = +500`，`entry_notional = 50000`
（名义 50,000 = 10 × 钱包，恰在 `leverage_tier = 10` 上限）：

```text
触发点：(5000 + 500×mark − 50000) × 10000 = 500×mark × 500
       5,000,000×mark − 450,000,000 = 250,000×mark
       mark = 450,000,000 / 4,750,000 ≈ 94.74

mark = 95 : unrealized = −2500, equity = 2500, notional = 47500
            margin_ratio = 526 bp > 500          → 不触发
mark = 94 : unrealized = −3000, equity = 2000, notional = 47000
            margin_ratio = 425 bp < 500          → 触发
```

即价格跌约 **5.3%** 即触发强平——这就是 10x 杠杆配 5% 维持率的脆弱程度，也是旗舰
问题要研究的连锁起点。

### 示例 3：强平数量

承示例 2 的合法仓位，`mark = 94`，`equity = 2000`，`position = 500`，
`target_bp = 1000`：

```text
q ≥ 500 − 2000 × 10000 / (94 × 1000) = 500 − 212.77 = 287.23
→ 向上取整至 min_quantity 步长：q = 288

平仓后：position = 212，notional = 212 × 94 = 19928
        equity  = 2000 − 288×94×5/10000 = 2000 − 13.54 = 1986.46
        margin_ratio = 1986.46 × 10000 / 19928 = 997 bp ≈ target 1000 ✓
```

差额 3 bp 来自手续费——这是 §4.2 说「用整数二分求最小可行 q」而非套用闭式解的原因：
闭式解忽略手续费，实现须验证平仓后确实 `≥ target_bp`，否则再加一个步长。

### 示例 4：穿仓与核销

同一仓位，但强平时簿上流动性枯竭，500 单位一路吃到均价 92 才成交完：

```text
avg_entry    = 50000 / 500 = 100
realized_pnl = 500 × (92 − 100) = −4000
fee          = 500 × 92 × 5 / 10000 = 23
wallet       = 5000 − 4000 − 23 = 977          # 仍为正，未穿仓
```

把仓位放大到 800（钱包 5000、`entry_notional` 80000，即 16x——**超出 10x 上限，
仅用于演示核销算术**），成交均价 88：

```text
realized_pnl = 800 × (88 − 100) = −9600
fee          = 800 × 88 × 5 / 10000 = 35.2
wallet       = 5000 − 9600 − 35.2 = −4635.2
position     = 0,  equity = −4635.2 < 0        → 穿仓

核销（§5.1 两步）：
  步骤 1（BREACHED）：wallet = −4635.2，C1 此时仍成立（负钱包也是钱包）
  步骤 2（核销）：
      wallet:                  −4635.2 → 0        Δ = +4635.2
      exchange_risk_pnl_units:  R → R − 4635.2    Δ = −4635.2
  C1 检验：+4635.2 + (−4635.2) = 0                ✓ 守恒
```

**符号是关键**：风险账户记**负数**（交易所承担损失）。若按上一版定义记正数，
C1 左侧会凭空多出 2 × 4635.2。

## 9. 与其他合同的衔接

| 文档 | 须同步的内容 |
|---|---|
| ADR-005 §4 | 预冻结改为「冻结初始保证金」，不再是全额名义金额 |
| 事件 Schema §4.2.1 | 分录字段改为永续口径；`negative_equity_units` → `risk_pnl_delta_units`（有符号） |
| 退化状态 §3.2 | 「现金不得为负」改为「钱包可短暂为负，随即核销」 |
| 指标字典 §5 | C1/C2 改为钱包/仓位守恒；§5.1 桥接降级为个体检验 |
| 代理策略 §5 | `max_position` 用初始保证金率计算，不用 `leverage_cap × equity / mark` |
| BENCH-001 | 初始仓位改为 0；`maintenance_ratio_bp` 口径改为保证金率 |
