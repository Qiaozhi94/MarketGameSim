## 1. 问题、目标与非目标

### 问题

在无外生基本面冲击的合成永续市场中，以真实人类交易者替换一个目标驱动代理，是否会
改变价格崩盘、流动性枯竭与强平连锁的发生和严重程度；若发生改变，该效应是否与人类的
激进订单、流动性撤回或风险减仓行为相一致？

这里的处理效应只指“在冻结参与者任务、信息集和操作窗口下，用人类决策替换指定代理
策略”。控制条件是同代码、配置、种子和初始状态的纯代理反事实，不是另一批人类受试者，
因此结论不得扩写为脱离协议与模型族的普遍“人类效应”。

### 目标

1. 预先冻结主要假设、估计量、样本量/停止规则、分配、顺序、排除规则和分析计划。
2. 为每个人类正式会话生成同种子纯代理反事实，唯一预定差异是目标代理的决策来源。
3. 分别估计人类替换对价格崩盘、流动性枯竭、强平连锁发生率和严重程度的双侧效应。
4. 预注册激进订单、流动性撤回和风险减仓指标，解释观察到的方向与时序。
5. 交付可复建、可审计、隐私最小化且明确限制的正式研究证据包。

### 非目标

- 不施加外生价格、基本面、新闻或订单流冲击。
- 不把三类主要结果压缩成综合崩盘得分，不因显著性选择性报告结果。
- 不把相关的机制指标称作已识别的因果中介；因果中介需要独立操纵或额外假设。
- 不比较人类与代理的裸反应速度，不允许正式运行通过暂停获得无限思考时间。
- 不使用 H1 自由交互、培训、理解检查、pilot 或失败调试运行建立正式结论。
- 不外推到真实市场，不提供投资建议，不接触真实资金或账户。

## 2. 用户场景

### US-301：执行配对的人在环实验（Priority: P1）

作为研究者，我希望参与者在冻结任务和操作窗口内替换指定代理，并为会话取得同种子纯
代理反事实，以便估计替换效应而不是比较不可比的市场路径。

**为什么是这个优先级**：没有配对反事实和唯一差异约束，H2 的主要估计量没有识别基础。

**独立测试**：对固定协议与种子分别生成纯代理和人类替换 manifest，机器比较除决策来源
外的全部冻结字段，并拒绝任何漂移。

**验收场景**：

1. Given 已冻结协议和合格参与者，when 启动正式 block，then 控制运行与处理运行共享
   配置、种子、初态、背景代理和逻辑时长。
2. Given 正式运行请求修改信息权限、窗口或制度参数，when 校验协议，then 会话在写入样本
   前 fail closed。

### US-302：审计人类行为机制（Priority: P1）

作为研究者，我希望将人类每次决策与盘口、成交、账户和强平因果链连接，以便判断主要
结果的变化是否与预注册行为机制一致。

**为什么是这个优先级**：项目要识别人类带来的反馈通道，而不只是报告两组终点均值。

**独立测试**：从人类决定事件回溯激进成交、撤单/改挂、深度变化、风险减仓和首次强平，
并验证指标只使用决定当时可见及随后发生的数据。

**验收场景**：

1. Given 一次人类正式会话，when 生成机制表，then 每个指标能追溯到规范输入和事件 ID。
2. Given 因果链缺失或指标定义未冻结，when 构建正式分析，then 样本被拒绝而非补猜。

### US-303：生成边界清晰的正式结论（Priority: P1）

作为审阅者，我希望独立查看三个结果家族的效应量、不确定性、排除项和限制，以便判断
数据支持放大、稳定还是未检出差异。

**为什么是这个优先级**：双侧假设允许任一方向或未检出；报告不能把“没有显著差异”包装
成等效，也不能用综合指标隐藏相反方向。

**独立测试**：从冻结 evidence index 重建分析，核对样本流图、配对完整性、三类结果、
机制分析和结论措辞。

**验收场景**：

1. Given 合格正式样本，when 生成报告，then 三类结果分别呈现配对效应和不确定性。
2. Given 数据不足或区间跨越预注册实质阈值，when 生成结论，then 报告“未建立方向性差异”
   而非声称无效应。

## 3. 范围与边界

### 范围内

- 单品种、合成加密式永续市场；无外生基本面信息或价格冲击。
- `PURE_AGENT_CONTROL` 与 `HUMAN_REPLACEMENT` 两条件的同种子配对 block。
- 一个真实参与者替换一个预先指定的目标驱动代理；其余代理、制度和初始状态冻结。
- 固定任务说明、信息权限、操作窗口、训练与理解检查、场景顺序分配。
- 价格崩盘、流动性枯竭、强平连锁三个结果家族及预注册机制指标。
- 匿名参与者 ID、同意/退出记录、系统故障和预注册排除状态。
- preview 与正式运行隔离、正式分析、报告、代表性回放和 evidence index。

### 范围外

- H1 `interactive` 自由操作数据和事后挑选的演示路径。
- 多个人类同时交易、参与者互相通信、排行榜和真钱激励系统。
- 外生新闻、基本面、价格注入或专门构造的压力冲击。
- 股票式制度、多品种、订单流预知、大资金执行算法和策略在线学习。
- 参与者人口统计差异、专业水平异质性或人格特质的验证性推断；除非另立预注册研究。

### 边界场景

- 参与者断线、客户端崩溃或运行完整性失败时，按冻结规则标记技术无效；不得根据结果决定
  是否排除，也不得事后补跑同一 block 而不留记录。
- 参与者撤回同意时，其数据按冻结同意与保留政策处理；身份映射不进入项目 artifact。
- 参与者超时按协议定义的 `NO_ACTION` 处理，不暂停市场，也不由实验员代替决策。
- 配对任一成员缺失时，该 pair 不进入主要配对分析；缺失数量与原因完整报告。
- 若主要分析发现方向变化，机制指标只能支持“与某行为通道一致”的解释，不能单独证明
  中介因果关系。
- 若三个家族方向不一致，逐项报告，不选择最符合故事的一项作为总体结论。

## 4. 需求

### 功能需求

### Requirement: 冻结 H2 协议与配对反事实（`FR-301`）

系统应在首个正式样本前冻结并内容寻址：研究问题、双侧假设、主要/次要估计量、三个结果
家族、机制指标、样本量与停止规则、目标代理、任务与激励、信息权限、操作窗口、训练、
理解检查、场景/顺序分配、排除/缺失规则、分析方法和结论语法。每个正式人类运行应绑定
一个除目标代理决策来源外字段相同的纯代理反事实。

#### Scenario: 拒绝不完整或漂移协议

- GIVEN 协议缺失任一冻结项或控制/处理 manifest 存在非处理字段差异
- WHEN 请求进入正式样本
- THEN 系统以稳定原因拒绝且不写 evidence index

### Requirement: 运行受控的人类替换会话（`FR-302`）

系统应提供 `HUMAN_REPLACEMENT` 条件：人类仅通过与代理相同的订单、撮合、保证金和强平
路径替换指定代理，在冻结信息集和有限操作窗口内决策；背景市场继续按逻辑时间推进，
正式会话不得暂停、单步或临时改参。

#### Scenario: 操作窗口超时

- GIVEN 正式会话的一个决策窗口结束且没有合法输入
- WHEN 调度器提交该窗口
- THEN 写入预定义 `NO_ACTION`，市场继续推进且不等待墙钟补录

### Requirement: 隔离培训、预览与正式样本（`FR-303`）

系统应区分 `training`、`preview`、`formal` 样本阶段。只有绑定冻结协议、满足完整性规则且
未命中预注册排除条件的 `run_mode = human-experiment, sample_stage = formal` 配对运行可
进入 H2 正式分析；H1 `interactive` 及其它阶段必须 fail closed。

#### Scenario: H1 数据伪装成正式样本

- GIVEN header 或 manifest 表明运行源自 `interactive` 或非正式阶段
- WHEN 正式证据入口消费该运行
- THEN 原子拒绝且不生成部分统计、报告或索引

### Requirement: 分别计算三个结果家族（`FR-304`）

分析应按冻结指标口径，分别计算价格崩盘、流动性枯竭和强平连锁的发生与严重程度，并按
参与者内重复测量/配对 seed block 估计 `HUMAN_REPLACEMENT - PURE_AGENT_CONTROL` 的双侧
效应量与不确定性。多重性、缺失和实质阈值必须按冻结计划处理。

#### Scenario: 结果方向不一致

- GIVEN 三个结果家族产生不同方向或不确定性
- WHEN 生成正式报告
- THEN 逐家族原样呈现，不生成未预注册的综合分数

### Requirement: 记录并分析预注册机制指标（`FR-305`）

系统应从可审计事件链计算至少三类人类行为：激进订单、流动性撤回、风险减仓；可附加
撤单/改挂、首次强平触发和终局权益。机制分析应预先声明时序与统计口径，默认解释为关联
和时序一致性，不声明因果中介。指标 ID、公式、单位、窗口、缺失语义和适用事件版本必须
写入 [`metrics-dictionary.md`](../../../research/metrics-dictionary.md)；冻结协议只引用其版本
与指标 ID，不得在实现、分析脚本或报告中另行定义同名口径。

#### Scenario: 指标无法追溯

- GIVEN 某机制值缺少规范输入、决定事件或后续市场事件引用
- WHEN 构建机制数据集
- THEN 将其标记为缺失并按冻结规则处理，不推断或手工补值

### Requirement: 生成 H2 正式证据包（`FR-306`）

系统应从冻结协议和 evidence index 单命令生成样本流图、配对检查、三类主要结果、机制
分析、敏感性分析、限制说明、代表性回放、机器可读结果和 manifest。报告结论必须区分
放大、稳定、未建立方向性差异，不把未拒绝零假设表述为等效。

#### Scenario: 重建正式结果

- GIVEN 发布的协议、evidence index 与代码版本
- WHEN 在新进程运行重建入口
- THEN 得到内容哈希一致的机器结果和语义等价的报告

### 数据 / 实体需求

- **DR-301**：`Protocol` 应保存协议 ID、内容哈希、冻结时间与所有预注册字段；
  `Participant` 只保存研究假名和资格/同意状态；`Assignment` 保存匿名参与者、seed block、
  场景顺序与条件；`ExperimentSession` 保存协议、分配、运行、阶段、完整性和排除状态。
  真实身份、联系方式与支付信息不得出现在事件日志、manifest、evidence index 或报告中。

### 事件 / Trace 需求

- **TR-301**：正式 `RUN_HEADER` 和 manifest 必须交叉绑定 `run_mode`、`sample_stage`、
  `protocol_id/hash`、匿名 `participant_id`、`assignment_id`、`pair_id`、条件、session order、
  目标代理和冻结窗口版本；未知、缺失或不一致均 fail closed。
- **TR-302**：每个人类窗口必须写规范决定或 `NO_ACTION`，并通过 `input_seq`、`intent_id`、
  `decision_event_id` 连接订单、撤单、成交、账本、盘口变化与强平事件；墙钟仅作依从性诊断，
  不改变逻辑事件排序。

### API / 接口需求

- **IR-301**：实验入口应提供版本化的 enroll/consent、training/check、assign、run 和 withdraw
  操作；`run` 只接受已冻结协议签发的 assignment，客户端不得暴露 pause、step 或改参。
- **IR-302**：正式 evidence guard 应验证运行模式、样本阶段、协议哈希、pair 完整性、排除
  状态和 artifact 哈希；验证完成前不得写部分聚合或 evidence index。

### UX 需求

- **UX-301**：参与者界面必须显示合成市场/无真实资金、标准化任务、当前逻辑进度、可见
  信息、本人账户、决策倒计时、输入结果和退出入口，不显示其他代理私有状态或未来事件。
- **UX-302**：正式会话应覆盖 waiting、active-window、submitted、no-action、completed、
  technical-abort 和 withdrawn 状态；实验员不得通过界面替参与者提交市场动作。
- **UX-303**：训练与正式运行必须有持续可见的阶段标识，避免参与者误认训练行动进入样本。

### 非功能需求

- **NFR-301**：纯代理控制应在冻结代码/配置/种子下逐事件可复现；人类会话应由规范输入
  重放。配对字段比较和 artifact 哈希必须机器验证。
- **NFR-302**：收集人类数据前必须完成适用的伦理/同意确认；坚持数据最小化、假名化、
  可退出和冻结保留政策。成果包不得包含可直接识别个人的信息。
- **NFR-303**：停止、排除、补跑和缺失处理只能依据冻结规则；系统故障必须留下审计记录，
  不得根据已观察的市场结果改变样本纳入决定。

## 5. 生命周期与不变量

```text
DRAFT_PROTOCOL -> FROZEN_PROTOCOL  开放问题关闭 / 审查、preview、伦理与功效条件通过
FROZEN_PROTOCOL -> TRAINING        参与者同意且资格校验通过
TRAINING -> ELIGIBLE               理解检查按预注册规则通过
ELIGIBLE -> ASSIGNED               分配表签发 participant-seed blocks 与顺序
ASSIGNED -> RUNNING                正式客户端校验协议和 assignment
RUNNING -> COMPLETED               全部窗口与 trailer 完整
RUNNING -> TECHNICAL_ABORT         冻结技术无效条件命中
* -> WITHDRAWN                     参与者行使退出
COMPLETED -> INCLUDED/EXCLUDED     仅按预注册规则裁决并留审计证据
INCLUDED pairs -> ANALYZED         样本量/停止规则满足且 evidence index 冻结
```

不变量：

- 首个正式样本后协议不可原地修改；任何修订必须新建协议版本并按冻结规则决定是否重启研究。
- 每个主要分析 pair 恰含一个纯代理控制和一个人类替换运行，且唯一预定差异为决策来源。
- 正式市场中不存在外生基本面或价格冲击；人类输入是处理的一部分而非隐藏冲击变量。
- 样本阶段、运行模式和协议完整性缺一不可；`interactive` 永不升级为 `formal`。
- 三类主要结果保持独立；所有预注册结果均报告。
- 纳入、排除、停止和补跑决定不读取处理结果。
- 身份映射与研究 artifact 分离；撤回、保留和删除遵循冻结同意政策。

## 6. 成功与验收

### 成功标准

- **SC-301**：首个正式样本前存在内容寻址、机器可验证且覆盖 FR-301 全部字段的冻结协议。
- **SC-302**：达到预注册样本量/停止条件，所有纳入运行均有完整 pair、因果链和哈希校验。
- **SC-303**：价格崩盘、流动性枯竭、强平连锁及三类机制指标按冻结计划分别输出效应量、
  不确定性、缺失与敏感性结果。
- **SC-304**：独立新进程可从 evidence index 重建正式结果；报告明确条件性结论、隐私边界、
  排除项和不可外推范围。

### 退出条件

| 退出 | 条件 | 证据 |
|---|---|---|
| E1 | 协议、功效/停止规则、同意/隐私、排除与分析计划冻结并通过机器校验 | frozen protocol + review record |
| E2 | 锁定客户端完成训练与 preview；正式证据门拒绝 H1、非正式阶段和协议漂移 | experiment-preview bundle + guard matrix |
| E3 | 按停止规则取得完整正式 pair；重放、配对与纳入裁决通过 | formal evidence index + sample flow |
| E4 | 三个结果家族与机制分析按预注册方法重建，未产生综合分数或因果中介越界 | machine results + analysis checks |
| E5 | 正式报告、代表性回放、限制与 manifest 可复建；外部审阅通过 | H2 delivery bundle + review record |

### 验收清单

- [ ] **AC-301** (`FR-301`, `DR-301`, `NFR-302`, `NFR-303`, `SC-301`): 不完整协议不能冻结；
      冻结后内容变化产生新哈希且旧 assignment 不可复用。
- [ ] **AC-302** (`FR-302`, `IR-301`, `UX-301`, `UX-302`): 正式客户端在有限窗口内完成合法
      决策和 `NO_ACTION`，不暴露暂停、单步、改参或信息特权。
- [ ] **AC-303** (`FR-303`, `IR-302`, `TR-301`): evidence guard 原子拒绝 interactive、
      training、preview、未知模式、协议漂移和不完整 pair。
- [ ] **AC-304** (`FR-301`, `FR-302`, `TR-301`, `NFR-301`, `SC-302`): 每个纳入 pair 的冻结

## 7. 测试、依赖与决策

### 测试策略

- 单元测试：协议冻结、assignment、窗口调度、配对比较、排除裁决、指标和结论语法。
- 集成测试：训练/正式会话、`NO_ACTION`、中止/撤回、重放、evidence guard 与原子输出。
- UI / E2E：有限窗口、阶段提示、信息闭集、无 pause/step/改参与参与者退出。
- 研究验证：冻结模拟数据恢复已知效应；preview 验证流程但永不进入正式证据；正式运行前
  完成分析代码盲测/锁定。
- 真实环境 / 手动验证：目标 Windows 环境训练与正式会话演练、断网与客户端故障恢复。

### 依赖

- 上游 Feature / Contract：已签收 v0.2.1；事件、代理、撮合、账户、指标与退化状态合同。
- 下游消费者：H2 分析、报告、回放、evidence index 和未来人类行为扩展研究。
- 外部 / 环境依赖：参与者招募、适用伦理/同意确认、时间安排和冻结激励方案。

### 决策与风险

| 决策 / 风险 | 结论或缓解 | 理由 | 后续 |
|---|---|---|---|
| 因果对象 | 估计“协议化人类替换指定代理”的效应 | 控制条件没有人类，不能识别抽象人类属性 | 报告限定参与者、任务与模型族 |
| 主要假设 | 双侧，允许放大、稳定或未建立方向差异 | 人类可撤回流动性，也可逆向供给或提前减仓 | 冻结实质阈值与区间解释 |
| 反事实 | 同 seed/config 配对纯代理运行 | 降低市场路径噪声并明确唯一差异 | 机器比较冻结字段 |
| 机制声明 | 关联与时序一致性，不默认称因果中介 | 处理后的行为变量存在中介混杂 | 若需因果中介另立操纵实验 |
| 学习/疲劳 | 训练隔离，场景顺序随机/平衡，模型处理参与者内重复 | 人类会随会话学习并疲劳 | 协议冻结 block 数和休息规则 |
| 选择与排除 | 预注册、结果盲的纳入和补跑规则 | 防止事后选择有故事的运行 | evidence index 保留样本流 |
