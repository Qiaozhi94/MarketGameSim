## 1. 问题、目标与非目标

### 问题

北极星把「owner 亲身参与、看自己的操作会给市场带来什么」列为**第一**研究问题，
但它此前没有任何里程碑承接：PRD 只有一行「H2-F 待立项」，0.4.1 明确把人类扰动
实验排除在范围外。三个具体风险因此长期敞口：

1. **数据格式未冻结**：owner 一旦开始自由游玩，前若干场的会话记录如果没有冻结格式，
   事后无法与 AI 基线配对，等于白玩。归档的 N-of-1 轨已经付过一次这种代价。
2. **命题形态未定**：「人类能否造成崩盘」在允许高杠杆与大单量的市场里是**自我实现**
   的——只要资金够、杠杆够，答案必然是「能」，这不构成发现，也不可证伪
   （PRD §13.5）。北极星的「扰动即数据、不存在错误用法」是**设计判据**，不是研究命题；
   两者之间缺一条桥接条款。
3. **现有 live 市场既不记录也不能逐位重放人类动作**（2026-10-15 核对）：`live_market`
   的 `main()` 不导出任何记录，owner 委托只留在内存里；注入路径有三处未加锁的竞态
   （`_seq`、`submitted_at`、`_safe_ts` 扫描待处理队列），委托落地的逻辑时点取决于 HTTP
   请求赶上哪一次 `advance()`，即墙钟抖动。

### 目标

1. 在 owner 第一场自由会话之前**冻结**会话 artifact 格式，使每一场都可逐位重放、可配对。
2. 让人类委托的落地点只由 `advance` 序号决定，消除注入路径的竞态，使同种子重放与原场
   的事件摘要逐位相同。
3. 提供同种子对照运行能力：无人类基线 vs 有人类，共享装配参数、种子与引擎配置指纹；
   N 来自**不同种子**（市场确定，同种子重复不含信息），N 由功效分析预注册。
4. 把研究命题写成**效应量命题**：报告稳定性指标集合的分布移动、不确定性区间与
   失效边界，而不是「是否发生过一次崩盘」。
5. 保证「扰动即数据」：不判定操作对错、不产出 owner 个人画像。

### 非目标

- 不做 owner 个人画像、不产出「owner 是什么样的交易者」的结论（北极星 §4）。
- 不把任何效应量外推为「人类」或「owner」对市场的影响——分析单元是市场运行（种子），
  处理是一段冻结的订单流（Q-601）。
- 不设固定场次、固定跨度或每窗一次动作的受控框架（北极星 §4；该框架已随 ADR-010 归档）。
- 不修改 L1 既有合同，也不修改 0.4.1 已冻结的市场质量与 stylized facts 口径。
- 不声明载体的市场真实性：载体 C 未达 0.4.3 的 `QUALIFIED`（SC-502 不稳定），只作实验载体。
- 不把 owner 会话数据并入 0.3.1 的 AI 研究声明或任何既有 evidence index。
- 不在本里程碑建立研究声明：证据级别为 `experiment-preview`（Q-601）。

## 2. 用户场景

### US-601：自由进出市场并留下可分析的记录（Priority: P1）

作为项目所有者，我希望随时进出一个持续运行的 AI 市场并自由下单，同时我的每一步都被
完整记录下来，以便事后分析我的参与对市场做了什么。

**为什么是这个优先级**：这是 owner 亲身参与项目的核心动机；记录格式没冻结，参与本身
就产生不了数据。

**独立测试**：一场自由会话结束后，仅凭落盘的会话 artifact 即可在同种子上重放出与原场
事件摘要逐位相同的运行，内容哈希稳定。

**验收场景**：

1. Given 一场自由会话，when 会话结束，then artifact 记录逐条动作的 `advance` 序号、分配的
   逻辑时间戳、`submitted_at`、`order_id`、载荷与墙钟时间戳，以及市场标识、种子、观察快照
   指纹与原场事件摘要。
2. Given 同一份 artifact，when 在同种子上重放，then 事件摘要与原场逐位一致；不一致即判失败。
3. Given owner 打开终端，when 市场尚未跑完预热，then 终端不开放下单；预热完成后 owner 进入
   一个已在运行的市场。

### US-602：比较有没有人类时的市场稳定性（Priority: P1）

作为项目所有者，我希望把「有我参与」的运行与「同种子、无人类」的基线运行放在一起比较，
以便看到我的介入把稳定性指标推动了多少，而不是只看一次运行的截图。

**为什么是这个优先级**：没有同种子对照，任何「人类让市场更不稳定」的说法都无法与
市场自身的随机波动区分。

**独立测试**：用一段冻结的动作序列驱动「有人类」臂，在预注册的种子集合上与同种子的
无人类基线配对，断言报告输出四个稳定性指标的效应量与区间，且基线臂逐点可复现。

**验收场景**：

1. Given 同一装配参数与同一种子，when 分别运行无人类基线与回放的有人类臂，then 两臂
   的指标可配对比较，基线臂逐点可复现。
2. Given 预注册种子集合上的一组配对运行，when 生成报告，then 报告给出效应量、不确定性
   区间与失效边界，并逐场列出原场个案；不给出「人类能否造成崩盘」的是非结论。

## 3. 范围与边界

### 范围内

- owner 自由会话 artifact 的**冻结格式**与其机器校验入口。
- live 市场注入路径的确定性修复：委托时间戳与 `submitted_at` 在 `advance()` 持锁取出时
  分配，`order_id` 序号在锁内递增；会话结束（含断线）时落盘 artifact。
- 载体 C 的 roster 按种子落盘，以及**预热快进**：开放终端前不按墙钟节拍推进到统计窗口起点。
- 同种子对照运行：无人类基线臂与有人类臂共享装配参数、种子与引擎配置指纹。
- 两种回放：**同种子重放**（必须与原场事件摘要逐位相同）与**开环跨种子回放**（把同一段
  动作序列按 `advance` 序号投到预注册的其他种子上）。
- 跨种子基线与功效分析；N、种子清单与最小可检出效应在正式配对前预注册。
- 稳定性指标集合与效应量报告：最大回撤、最大涨幅、大波动频次、盘口可用率。
- owner 委托在事件因果链上的参与者类别标识（与 AI 委托同路径、可区分）。

### 范围外

- L1 既有合同的任何修改；0.4.1 的质量门限与 stylized facts 口径的任何修改。
- owner 个人画像、操作对错判定、固定场次/跨度/节奏的受控框架。
- Web 终端的界面重做（沿用 0.4.1 live 市场自带的 owner 终端页面）。
- 把 owner 数据并入 AI 研究声明或任何既有 evidence index。
- 研究声明本身与 `formal-research` 升级：须另立预注册（Q-601）。
- 以锚定 roster `2425a8…`（载体 B）为对照载体的开环回放：**可选**，不作为任何退出条件（见 tasks §5）。

### 边界场景

- owner 中途离开或断线：会话 artifact 必须落盘为**完整的短会话**，不得丢失已发生的动作。
- owner 执行极端操作（满杠杆、单边扫单）：照常记录，不拦截、不判错——扰动即数据。
- 风控拒绝的动作：照常记录其载荷与原因码；回放时按同样载荷投递，由风控按当时状态判定。
- 同种子重放与原场事件摘要不一致：判失败并给稳定原因码，不得把重放臂结果当作原场报告。
- 开环回放中，撤单目标在该种子上已成交或不存在：按既有撤单语义处理并记录原因码，
  不得静默跳过。
- 预热结束时仍有代理处于冷启动锚：统计窗口不成立，判 `NOT_APPLICABLE` 并拒绝开放终端。
- 动作落在统计窗口之后：照常记录，计入报告的「窗口外动作数」，不进入指标计算。
- 指标在某臂上退化（如窗口内零成交、单边空簿）：如实报告退化，不得用退化臂算出效应量
  （`effect = 0.0 / CI = [0,0]` 全表出现属零功效，不是零结果）。

## 4. 需求

### 功能需求

### Requirement: 冻结 owner 自由会话 artifact 格式（`FR-601`）

- **FR-601**：系统应在 owner 第一场自由会话之前冻结会话 artifact 格式，记录会话标识、
  `roster_id`、种子、引擎配置指纹、逐条动作（`advance` 序号、分配的逻辑时间戳、
  `submitted_at`、`order_id`、载荷、墙钟时间戳、受理原因码）、观察快照指纹、原场事件摘要
  与内容哈希；对齐只用 `advance` 序号与逻辑时间戳，墙钟时间戳只作辅助字段。格式变更必须
  升版本号并留 git 痕迹，不得就地改写已落盘会话的语义。

### Requirement: 同种子对照运行（`FR-602`）

- **FR-602**：系统应支持在同一装配参数与同一种子下运行「无人类基线」与「有人类」两臂，
  并按配对关系组织结果；基线臂在无人类介入时必须逐点可复现。有人类臂有两种来源：
  ① **同种子重放**——在原场种子上按 `advance` 序号重放，事件摘要必须与原场逐位相同，
  不一致即 fail closed；② **开环跨种子回放**——把同一段动作序列按 `advance` 序号投到
  预注册的其他种子上，报告中标注为「固定订单流扰动」，不表述为人类对市场的反应。

### Requirement: 稳定性效应量报告（`FR-603`）

- **FR-603**：系统应对一组配对运行输出稳定性指标（最大回撤、最大涨幅、大波动频次、
  盘口可用率）的分布移动、不确定性区间与失效边界。分析单元是种子：每个种子上取两臂
  指标之差，效应量为差值中位数，区间为配对 bootstrap 的 [5%, 95%] 分位区间；主效应量
  来自开环跨种子回放，原场（同种子）配对逐场列为个案、不并入主效应量。报告不得以
  「是否出现过崩盘」作为结论形态，也不得在任一臂退化时输出效应量。

### Requirement: 扰动即数据（`FR-604`）

- **FR-604**：系统不得对 owner 的操作做对错判定或行为画像；会话 artifact 与报告中
  不得出现「错误用法」「违规操作」一类判定字段，也不得包含直接身份信息。

### Requirement: 载体与预热（`FR-605`）

- **FR-605**：实验载体为 0.4.3 预注册扫描格 `count = 6`、`sensitivity_x1000 = 150`（其余
  固定项同 0.4.3 T1109：默认装配加价值族、响应函数 `linear_saturating_v1`），按种子落盘为
  可由 `--roster-file` 打开、内容哈希到 `roster_id` 的清单；报告与 artifact 声明该载体未达
  0.4.3 `QUALIFIED`、SC-502 不稳定、只作载体。live 市场在开放 owner 终端前不按墙钟节拍
  推进至统计窗口起点（0.4.1 口径：`max(冷启动退出, 3660 逻辑秒)`）；该起点不成立时拒绝开放。

### 数据 / 实体需求

- **DR-601**：`PerturbationSession` 应记录会话标识、臂标识（`baseline` / `human`）、
  回放模式（`original` / `same_seed_replay` / `open_loop_replay`）、`roster_id`、种子、
  动作序列（字段见 FR-601）、观察快照指纹、原场事件摘要与内容哈希，并可由会话标识重放。
- **DR-602**：`PerturbationEffectReport` 应记录预注册文件哈希、配对集合（种子、两臂运行
  标识、回放模式）、每个指标的两臂分布、逐种子差值、效应量、不确定性区间、失效边界、
  退化判定与窗口外动作数；退化时效应量字段必须缺省而不是填 0。

### 事件 / Trace 需求

- **TR-601**：owner 委托应走与 AI 委托完全相同的撮合、账本与风控路径，并在既有决策
  记录中携带参与者类别标识，使事件链可区分人类与 AI 来源，而不新增事件类型。

### API / 接口需求

- **IR-601**：人类参与入口沿用 0.4.1 live 市场的 owner 终端与非阻塞注入路径，不新增内核
  接口；会话回放入口接受冻结格式的动作序列，按 `advance` 序号在推进循环中投递。

### 非功能需求

- **NFR-601**：人类在场不得改变 L1 语义与 AI 侧确定性；无人类基线运行在同种子下逐点可复现；
  人类委托的落地点只由 `advance` 序号与载荷决定，与墙钟到达时间、HTTP 线程调度无关。
- **NFR-602**：会话 artifact 与报告不含直接身份信息，不进入任何既有 evidence index，
  也不与 0.3.1 的 AI 研究声明合并统计。

## 5. 生命周期与不变量

```text
UNSCHEDULED    -> FORMAT_FROZEN   会话 artifact 格式冻结并有机器校验入口
FORMAT_FROZEN  -> BASELINE_READY  载体落盘、预热成立，无人类基线臂可在同种子下逐点复现
BASELINE_READY -> POWERED         跨种子基线完成功效分析，N / 种子清单 / 最小可检出效应已预注册
POWERED        -> PAIRED          同种子重放与原场逐位一致，开环回放在预注册种子上与基线配对
PAIRED         -> REPORTED        效应量报告产出（含区间与失效边界）
PAIRED         -> DEGENERATE      任一臂退化：如实报告退化，不输出效应量
POWERED        -> REPLAY_DIVERGED 同种子重放与原场事件摘要不一致：fail closed，不进入配对
```

不变量：

- 会话 artifact 格式一经冻结，变更须升版本号并留 git 痕迹；已落盘会话不被改写。
- 「扰动即数据」：不判定 owner 操作对错，不产出个人画像。
- 研究命题是效应量命题，不是存在性问题；「人类能否造成崩盘」不作为结论形态。
- 分析单元是种子；效应量只陈述「该订单流在载体 C 上使指标移动多少」，不外推至人类。
- 预注册文件提交后不得改动 N、种子清单与最小可检出效应；扫描入口只读该文件。
- 退化臂不得产出效应量：`effect = 0.0 / CI = [0,0] / p = 1.0` 全表出现是零功效证据。
- owner 数据永不并入 AI 研究声明与既有 evidence index。

## 6. 成功与验收

### 成功标准

- **SC-601**：会话 artifact 格式在第一场自由会话之前冻结，任一场会话仅凭 artifact 即可
  在同种子上重放出与原场事件摘要逐位相同的运行，内容哈希稳定。
- **SC-602**：同装配参数、同种子下，无人类基线臂逐点可复现；有人类臂可由冻结的动作
  序列以同种子重放与开环跨种子回放两种方式运行，并与基线配对。
- **SC-603**：报告以效应量形态给出结论——四个稳定性指标的逐种子差值中位数 + 配对
  bootstrap [5%, 95%] 区间 + 失效边界；任一臂退化时输出退化判定而非效应量。指标口径
  （owner 2026-10-15，Q-602），统计窗口为 0.4.1 口径 `[max(冷启动退出, 3660 s), 5700 s]`，
  两臂同窗：
  - **盘口可用率**：直接采用 0.4.1 已冻结的 `two_sided_book_uptime`（1 秒网格、双边都有
    报价才计可用），只取窗口；
  - **大波动频次**：采用 0.4.1 SC-503 的事件定义与冻结常量（相邻有成交分钟收盘价变动
    ≥ 3%，或强平连锁深度 ≥ 1），只计窗口内事件，按窗口分钟数折算为每逻辑小时频次；
  - **最大回撤**：最新成交价在窗口内、峰值自窗口起点重置的最大峰谷跌幅
    `max_t (1 − P_t / max_{W0≤u≤t} P_u)`；
  - **最大涨幅**：与最大回撤对称的谷峰涨幅 `max_t (P_t / min_{W0≤u≤t} P_u − 1)`；
  - 最大回撤与最大涨幅在 0.4.1 中无冻结口径（0.4.1 报告 §12 记录过累计峰值口径的缺陷），
    由 `T1121` 写入指标字典后冻结，本 spec 不另存第二份。
- **SC-604**：artifact 与报告不含对错判定、行为画像字段与直接身份信息。
- **SC-605**：正式配对前，在预注册的 20 个种子上跑无人类基线，估计四个指标的跨种子
  标准差，产出功效分析报告；N、开环回放种子清单与最小可检出效应写入单一预注册文件并
  **先于任何正式配对运行提交**，配对入口只读该文件，文件缺失或哈希不一致时 fail closed。

## 7. 测试、依赖与决策

### 测试策略

- 单元测试：artifact 格式校验（字段缺失、版本号不匹配、含画像字段）的正反用例；
  四个指标在构造价格序列上的数值口径（含窗口起点重置）；效应量与配对 bootstrap 在构造
  输入上的口径；退化输入的判定；预注册文件的哈希守卫。
- 集成测试：同种子基线复现、同种子重放逐位一致、开环回放与配对、并发注入的确定性、
  人类与 AI 委托并存的批量因果链、预热与终端开放、产物不进入 evidence index 的守卫。
- 真实环境 / 手动验证：owner 在 loopback 终端上完成一场自由会话，导出 artifact 并重放。
- 既有回归：0.4.1 的市场质量门、0.4.3 的锚定市场门、0.3.1 配对轨与 0.3.2 终端测试必须全绿。

- 上游 Feature / Contract：`0.4.1`（live 市场载体、`StrategyRoster`、质量指标与统计窗口）、

### 决策与风险

## 8. 待确认问题

- [x] Q-601: 本里程碑最终证据级别——同种子对照 + 动作回放成立后，`experiment-preview` 是否可升级为 `formal-research`？须先回答 SOP §2「交互运行不进统计」的适用边界：分析单元是市场运行（seed）还是人？升级前不得声明任何研究结论。 — 决策：owner 2026-10-15 裁决分析单元为**市场运行（种子）**，处理为一段冻结的订单流，命题为「该订单流在载体 C 上使指标移动多少」，不外推至人类或 owner；本里程碑证据级别维持 `experiment-preview`，升级 `formal-research` 须另立预注册；SOP §2 作用域说明同步修订。
- [x] Q-602: 三个稳定性指标（最大回撤、大波动频次、盘口可用率）各取 0.4.1 已冻结的哪一版计算口径，窗口与分位数如何定？ — 决策：owner 2026-10-15 裁决见 SC-603——盘口可用率直接用 `two_sided_book_uptime`；大波动频次用 SC-503 定义与常量、只加窗口；最大回撤改为窗口内峰值重置的峰谷跌幅，并新增对称的最大涨幅（PRD §15 指标集合同步修订）；窗口为 0.4.1 口径至 5700 s、两臂同窗，配预热快进（FR-605）；效应量取逐种子差值中位数，区间为配对 bootstrap [5%, 95%]。
- [x] Q-603: 每个配对需要多少次重复（N）才有可接受的功效，功效分析在哪一步做？ — 决策：owner 2026-10-15 裁决 N 指种子数（同种子重复不含信息）；功效分析放在 Phase 1 末尾，用 20 个种子的无人类基线估计跨种子标准差，N、种子清单与最小可检出效应在正式配对前预注册（SC-605）。
- [x] Q-604: owner 单场会话不可重复，重放臂与原场若有差异如何处置——只报原场，还是报重放臂并声明差异？ — 决策：owner 2026-10-15 裁决同种子重放必须与原场事件摘要逐位相同，不一致即 fail closed，不作为「差异」报告；主效应量来自开环跨种子回放（标注「固定订单流扰动」），原场配对逐场列为个案（FR-602、FR-603）。
