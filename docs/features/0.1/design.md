# Implementation Plan: Belief Testing Laboratory

**对应规格**：[`spec.md`](spec.md)（状态见其 frontmatter）  
**创建日期**：2026-08-01

本文是**架构层**：组件边界、依赖方向、数据模型、测试策略。**算法层在实现合同中**
（`contracts/`），本文不重复它们的内容，只声明它们各自约束哪一层。

## 1. 技术上下文

| 项 | 取值 |
|---|---|
| 语言/版本 | Python ≥ 3.11 |
| 核心领域层依赖 | **仅标准库**（KR-005）——不含 NumPy、pandas |
| 分析/报告层依赖 | 允许 NumPy、SciPy、pandas（不被核心层导入） |
| 存储 | 事件日志 JSONL（规范序列化，ADR-001 §7）；分析产物 JSON 表格（报告层消费格式，R-A；Parquet 仅作归档写出，T507） |
| 测试框架 | pytest + 属性测试（`hypothesis` 可选，仅测试层） |
| 性能目标 | BENCH-001 归一化耗时 ≤ 10 秒，且覆盖断言全满足 |
| 代码风格 | ruff（`line-length = 100`，见 `pyproject.toml`） |

**为什么核心层禁 NumPy**：KR-004 的随机流已改为纯标准库 `blake2b` 派生
（代理策略 §10.1），KR-002 的时间是整数纳秒，ADR-001 的金额是最小单位整数——
核心层没有任何浮点数组运算。引入 NumPy 只会带来跨版本的浮点行为差异，威胁
NFR-001 的逐事件一致性。

## 2. 组件边界与依赖方向

```text
┌──────────────────────────────────────────────────────────┐
│ L4  呈现与报告        replay/ · report/                   │
│     单文件 HTML 回放器、条件性结论、证据包                  │
└────────────────────────┬─────────────────────────────────┘
                         │ 只读事件日志
┌────────────────────────┴─────────────────────────────────┐
│ L3  实验编排          experiment/                         │
│     批量运行、配对对照、参数扫描、排除与统计                 │
└────────────────────────┬─────────────────────────────────┘
                         │ 驱动
┌────────────────────────┴─────────────────────────────────┐
│ L2  代理与信念        agent/                              │
│     因子、信念权重、目标仓位、订单意图、做市商               │
└────────────────────────┬─────────────────────────────────┘
                         │ 提交意图 / 接收观察
┌────────────────────────┴─────────────────────────────────┐
│ L1  确定性内核        kernel/ · book/ · ledger/ · eventlog/│
│     事件队列、订单簿、账户、保证金、强平、日志               │
└──────────────────────────────────────────────────────────┘
```

**依赖规则（单向，不得逆转）**：

- L1 不导入 L2/L3/L4 中的任何模块；
- L4 只消费事件日志，**不被 L1—L3 引用**（NFR-004、v0.1 / D-7）；
- L2 通过接口与 L1 交互，不直接触碰订单簿内部结构；
- 制度钩子（v0.1 / D-1）由 L1 定义接口、由配置注入实现，**撮合核心不含制度判断**。

## 3. 数据模型

### 3.1 值对象（全部不可变，全部整数）

```text
Price      = int   # price_ticks，单位 tick_size
Quantity   = int   # qty_units，单位 min_quantity（有符号时表示仓位方向）
Cash       = int   # cash_units，单位 cash_unit
Bp         = int   # 万分数（保证金率、费率）
Nanos      = int   # 逻辑时间
```

**不引入 `Decimal` 到领域状态与撮合/账本运算**——`Decimal` 只出现在配置解析
（ADR-001 §2）、因子计算与确定性分布变换（代理策略 §9—§10），且结果在进入领域
状态前已量化为整数。

### 3.2 核心实体

| 实体 | 关键字段 | 不变量 |
|---|---|---|
| `Order` | `order_id`、`agent_id`、`side`、`price_ticks`、`qty_units`、`transaction_seq`、`origin` | 价格已对齐 tick；数量 > 0 |
| `Account` | `wallet_units`、`position_units`、`entry_notional_units`、`reserved_units`、`state` | 见 §3.3 |
| `QueueEvent` | `(timestamp, priority_class, enqueue_seq)`、`event_id` | 入队键唯一，且满足 KR-006 |
| `LogRecord` | `(timestamp, transaction_seq, record_index)`、`event_id`、因果外键 | 日志键唯一且严格递增 |
| `Trade` | `trade_id`、`price_ticks`、`qty_units`、两条 `posting` | `postings` 长度恒为 2 |

### 3.3 全局不变量（逐事件断言）

```text
C1: Σ position_units ≡ 0
C2: Σ (wallet_units − entry_notional_units) + 交易所费用 + exchange_risk_pnl
    = Σ wallet_units(0)
```

两式**整数精确相等**，不得写成浮点容差断言。期望值见
[验收向量](../../contracts/acceptance-vectors.md)。

### 3.4 账户状态机

```text
ACTIVE ──保证金率 < maint_bp──▶ PENDING_LIQUIDATION
   ▲                                    │
   └────保证金率恢复 ≥ maint_bp─────────┘
                                        │ 全平后 wallet < 0
                                        ▼
                                   LIQUIDATED（终态）
```

`LIQUIDATED` 后不再产生订单意图，已挂订单全部撤销（退化状态 §3.4），不参与后续
任何扫描。

## 5. 测试策略

### 5.1 五个层级

| 层级 | 对象 | 判据来源 |
|---|---|---|
| **向量测试** | 账户引擎 | [验收向量](../../contracts/acceptance-vectors.md) 十个案例的整数期望值 |
| **单元测试** | 订单簿、事件队列、配置解析 | 订单簿向量 OB-1—OB-9b；KR-006 单调性 |
| **属性测试** | 守恒、定序、舍入 | 随机订单流下 C1/C2 恒成立；`enqueue_seq`、`transaction_seq`、`record_index` 各自满足合同 |
| **确定性测试** | 全链路 | 同种子两次运行的事件摘要哈希相等（SC-002） |
| **重放测试（终态）** | 事件日志 | 仅凭日志重建**账户与订单簿**终态；因果链引用完整性（SC-006）。属 0.1.1 E6 |
| **重放测试（逐帧）** | 事件日志 | 仅凭日志重建**每个已提交事务后的完整状态**，与内核快照逐帧逐字段相等（SC-008）。属 0.1.4 E1 |

两层重放不可互相替代：终态相等只说明净效果对，逐帧相等才排除「中途走偏又走回来」。
逐帧重放的第一帧来自强制初态快照（事件 Schema §4.6.3）。

### 5.2 属性测试的关键不变量

随机生成订单流（含极端价格、边界数量、自成交、跨档）后断言：

1. C1、C2 在**每个事件后**成立；
2. **逐事件价值断言**——必须含 `entry_notional`：

   ```text
   Σ(postings.wallet_delta − postings.entry_notional_delta)
     + 交易所费用增量 + 交易所风险账户增量 = 0
   ```

   **不能写成 `Σ wallet_delta + 费用 + 风险 = 0`**：跨价换手时该式不成立。
   反例（验收向量案例 2 第二笔，A 在 110 平掉成本 100 的 10 手、C 在 110 建仓）：
   `Σwallet_delta = +100`、`Σentry_delta = +100`，旧式得 +100 ≠ 0 会把合法成交判为
   失败；含 `entry_notional` 后为 0；
3. 队列事件按 `queue_key` 弹出，日志记录按 `log_key` 严格递增且无重复；
4. 订单簿的价格优先与到达事务 `transaction_seq` 时间优先不被违反；
5. 账户状态机不出现非法转移（如 `LIQUIDATED → ACTIVE`）。

### 5.3 测试与合同的关系

**合同是判据，测试是执行。** 测试失败时先判断是实现错还是合同错——若合同错，
按 PRD §10 的变更规则修合同并重算期望值，**不得直接改测试期望值迁就实现**。

## 6. 风险与权衡

| 风险/决策 | 影响 | 缓解 |
|---|---|---|
| 核心层禁 NumPy 使性能受限 | BENCH-001 可能超 10 秒 | 先测量再优化；`max_transactions` 可下调（benchmarks/README §4）；整数运算本身比浮点快 |
| O(N) 全账户风险扫描 | 每笔成交 O(账户数) | 第一版接受（190 账户）；瓶颈时引入按强平价排序的索引 |
| 全撤重报使撤单率偏高 | 簿的瞬时深度波动放大 | 已知并声明（代理策略 §12）；撤单率作为观测量报告，不解读为策略特征 |
| 合同与实现分离，可能漂移 | 实现悄悄偏离合同 | 向量测试直接引用合同期望值；合同变更须 ADR + `schema_version` |
| 六份合同的交叉引用维护成本 | 改一处忘一处 | 链接检查纳入 CI；章节号引用有效性检查（本轮已建立脚本化核查） |
