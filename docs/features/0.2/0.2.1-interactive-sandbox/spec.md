# 0.2.1：H1 手动交易沙盒

> Spec: `spec.md` | Design: `design.md` | Tasks: `tasks.md`

## 0. 来源与意图

- **版本规格**：[`../spec.md`](../spec.md)（US-201—US-203、FR-201—FR-208）。
- **PRD 来源**：[`../../../market-game-sim-prd.md`](../../../market-game-sim-prd.md) §15 H1。
- **架构来源**：[`../../../market-game-sim-architecture.md`](../../../market-game-sim-architecture.md)
  §1、§3。
- **上游合同**：[`event-schema.md`](../../../contracts/event-schema.md)、
  [`agent-strategy.md`](../../../contracts/agent-strategy.md)、
  [`matching.md`](../../../contracts/matching.md)、
  [`margin-and-account.md`](../../../contracts/margin-and-account.md)。
- **上游决策**：v0.1 根规格 D-7、PRD Q-016。
- **功能类型**：user-facing / runtime / event / validation。
- **规格模式**：full。
- **变更类型**：ADDED。
- **一句话意图**：让单个交易者在隔离的本地合成市场中观察、下单、撤单并确定性重放，
  同时保证交互数据永不进入研究证据。

## 1. 问题、目标与非目标

### 问题

当前系统只能离线回放代理已经完成的运行。交易者无法在市场推进过程中观察可见信息、
提交行动并看到同一事件链上的成交、账户和风险后果，因此难以用亲手操作建立机制直觉。

### 目标

1. 交付单机单人的隔离交互会话，支持观察、限价/市价下单、撤单和账户反馈。
2. 把每个人类输入规范化并保存，使完整会话可以在新进程中确定性重放。
3. 让人类订单走现有生产撮合与风控路径，不增加特殊权限或 UI 专用业务逻辑。
4. 用 fail-closed 门禁把 `interactive` 运行与研究统计、报告和 evidence index 隔离。
5. 生成可打开的运行说明与离线回放，形成 H1 用户交付。

### 非目标

- 不连接真实市场、真实账户或资金，不提供交易建议。
- 不开展 H2 人在环正式实验，不声称交互结果具有统计或现实外推意义。
- 不做多人会话、公网访问、账户认证、排行榜、移动端或协同交易。
- 不实现股票式制度、多品种、策略学习、订单流预知者或大资金执行者。
- 不要求人类在速度上与代理公平——这是对版本根已确认决策 4 的显式收窄；人类可暂停
  思考，但信息特权限制仍完整生效（见 FR-202），交互模式不用于速度或信息能力对照。

## 2. 用户场景

### US-201：完成一次手动交易会话（Priority: P1）

作为交易者，我希望在本地观察市场与自己的账户，提交或撤销订单并看到结果，以便理解
订单流、成交、仓位和保证金之间的联系。

**为什么是这个优先级**：这是 H1 的最小用户价值；没有完整动作闭环，后续重放没有对象。

**独立测试**：用固定配置启动会话，经客户端完成一次成交、一次拒单和一次撤单，检查
可见状态、事件链与账户结果。

**验收场景**：

1. Given 会话运行且买卖簿可用，when 用户提交合法限价单，then 订单按现有规则成交或挂单。
2. Given 用户有活动订单，when 用户撤销该订单，then 订单离簿并显示稳定处理结果。
3. Given 用户提交非法或风险不足订单，when 系统处理输入，then 明确拒绝且不产生部分提交。

### US-202：保存并重放决策链（Priority: P1）

作为交易者，我希望保存一次会话的输入序列并离线重放，以便逐步审查每次决策造成的市场
与账户变化。

**为什么是这个优先级**：可重放是项目可信度边界，也是交互模式区别于一次性游戏的核心。

**独立测试**：在两个新进程中以同一代码、配置、种子和输入序列运行，比较事件摘要与回放帧。

**验收场景**：

1. Given 已结束的交互会话，when 使用其输入序列重放，then 事件摘要和逐帧状态完全一致。
2. Given 输入序列被篡改或截断，when 重放，then 校验失败并指出输入位置，不声称复现成功。

### US-203：确认研究隔离（Priority: P1）

作为研究者，我希望正式研究入口拒绝所有交互产物，以便人类学习、疲劳和自由选择不污染
预注册实验。

**为什么是这个优先级**：证据污染属于阻断性风险，必须与首个交互入口同时交付。

**独立测试**：把完整和篡改的交互 manifest 分别传入正式报告、统计和 evidence guard，
全部必须 fail closed 且不写 evidence index。

**验收场景**：

1. Given `run_mode = interactive`，when 调用正式研究入口，then 入口以稳定错误码拒绝。
2. Given manifest 缺失 `run_mode`，when 调用正式研究入口，then 按未知来源拒绝而非默认放行。

## 3. 范围与边界

### 范围内

- 单机、单人、单品种、加密式永续市场。
- 固定配置与种子启动；背景代理继续由现有目标驱动运行器驱动。
- `AGENT_OBSERVE` 闭集内的市场信息，以及用户自己的账户/持仓/活动订单与输入处理结果。
- 限价单、市价单、撤单；开始、暂停、继续、单步、结束。
- 规范输入记录、确定性重放、离线 HTML 回放和 `engineering-demonstration` 成果包。
- 正式研究入口的交互证据拒绝矩阵。

### 范围外

- 真实行情、真实资金、策略推荐和自动替用户下单。
- 用户查看代理私有信息、未来事件或订单到达前的内部队列。
- 当前尚未完成的 K 线（与代理同口径，理由见 `agent-strategy.md` §1）。
- 超过 k=10 tick 的盘口深度。
- 修改既有撮合、账本、保证金与强平经济合同。
- H2 的随机分组、信息权限实验、操作窗口、学习/疲劳控制与统计推断。

### 边界场景

- 空簿、单边簿或无成交时，客户端显示明确空状态，市价单按现有 IOC 语义处理。
- 暂停时已提交事务保持提交，未处理输入不得半进入内核；继续后按 `input_seq` 处理。
- 结束或中止后到达的输入一律拒绝，不能重新激活会话。
- 用户账户强平或破产时沿用现有账户权限；UI 不得提供绕过风险状态的动作。
- 客户端断开不等于市场事务回滚；会话按冻结的恢复策略继续、暂停或中止。

## 4. 需求

### 功能需求

- **FR-201**：系统应从合法配置与种子创建唯一交互会话和人类参与者，并在首条
  `RUN_HEADER` 写入 `run_mode = "interactive"`。
- **FR-202**：人类观察面必须是 [`AGENT_OBSERVE` 信息集](../../../contracts/agent-strategy.md)
  的子集：买卖各 k=10 tick 深度、上次观察以来的成交增量、只到上一根完整 K 线的序列，
  以及人类参与者自身账户、持仓、活动订单与风险状态。未完成 K 线、超出 k 档的深度、未来
  事件、其他代理内部状态与未公开通信队列一律不可见。
- **FR-203**：人类限价单、市价单和撤单必须通过现有订单入口、制度钩子、保证金准入、
  自成交阻止、撮合与账本事务；接受和拒绝路径都必须原子化并可观察。
- **FR-204**：会话控制器必须支持开始、暂停、继续、单步和结束；墙钟输入只负责分配逻辑
  时间，暂停期间市场逻辑时间不推进；`assigned_timestamp` 单调不减，输入全序
  `(assigned_timestamp, input_seq)` 严格递增。
- **FR-205**：系统必须保存规范输入序列，并能在新进程中用相同代码、配置和种子重放；
  重放须比较输入哈希、事件摘要哈希和逐帧状态。
- **FR-206**：正式研究运行、批量统计、报告和 evidence index 入口必须拒绝
  `run_mode = interactive`、manifest 缺失/未知模式，以及 manifest 与首条
  `RUN_HEADER.run_mode` 不一致的候选产物。guard 以 header 为模式真源、manifest 只作交叉
  校验；任一拒绝均不得产生部分证据。
- **FR-207**：本地客户端必须同时提供市场、账户、活动订单、输入结果与会话状态视图，
  并覆盖 loading、empty、paused、rejected、completed、aborted UI 状态；它们与会话状态的
  映射由 design §6 唯一规定。
- **FR-208**：交付入口必须在单目录生成 `RUN.md`、manifest、事件日志、规范输入序列和
  离线 `replay.html`；manifest 与回放须绑定同一会话。

### 数据 / 实体需求

不适用：H1 不引入数据库或长期服务端实体；规范输入序列和 manifest 属文件 artifact，
其字段由 TR-201/TR-203 与 design §3 定义。

### 事件 / Trace 需求

- **TR-201**：每条规范输入记录必须含 `input_seq`、动作枚举、规范 payload、
  `assigned_timestamp`、`accepted`、稳定 `reason_code` 和可空墙钟诊断时间；除墙钟字段外
  全部进入输入序列哈希。`input_seq` 全局严格递增；`assigned_timestamp` 单调不减，同一
  已提交事务边界上的多条输入共享同一逻辑时间，输入全序由
  `(assigned_timestamp, input_seq)` 唯一确定。
- **TR-202**：被接受的人类交易决定必须写入 `AGENT_DECIDE`，使用
  `rule_id = "human"`，并通过现有 `intent_id`、`decision_event_id` 等因果外键连接订单、
  成交与账户记录。
- **TR-203**：manifest 必须含 `run_mode`、代码版本、配置哈希、种子、输入序列哈希、事件
  摘要哈希、终止状态及各 artifact 的内容哈希。manifest 的 `run_mode` 必须与事件日志首条
  `RUN_HEADER.run_mode` 完全一致；该 header 字段为 `HASH_EXCLUDE`，事件摘要哈希不覆盖它，
  因此必须由独立断言保证一致，不得依赖摘要哈希间接证明。

### API / 接口需求

- **IR-201**：交互适配器必须提供版本化的 `observe`、`place_order`、`cancel_order` 和
  `input_result` 接口；同一动作不得同时存在 UI 专用与测试专用业务实现。
- **IR-202**：会话控制接口必须提供 `start`、`pause`、`resume`、`step`、`end`，并对非法
  状态转换返回稳定错误码。
- **IR-203**：统一入口必须支持 `new` 与 `replay` 两种模式；`replay` 只消费已保存输入，
  不等待新的墙钟输入。

### UX 需求

- **UX-201**：主视图必须在一次查看中呈现价格/K 线、买卖盘摘要、会话状态、账户权益、
  持仓、保证金状态和活动订单；K 线只到上一根完整 K 线，盘口深度不超过 k=10 tick。
- **UX-202**：下单与撤单必须显示规范化后的价格/数量、处理状态和稳定拒绝原因；不得仅在
  日志中报告用户错误。
- **UX-203**：界面必须持续显示“合成市场、非交易建议、无真实资金”的边界提示。

### 非功能需求

- **NFR-201**：墙钟时间、刷新频率、客户端类型和渲染耗时不得影响事件摘要；确定性口径为
  相同代码、配置、种子与规范输入序列。
- **NFR-202**：输入、日志或客户端故障不得留下半提交状态；会话必须产生完整 trailer，或
  以稳定 abort code 明确标记不完整。
- **NFR-203**：默认只监听 loopback，离线可运行；不得请求、读取或保存交易所凭据、钱包
  密钥与真实账户标识。
- **NFR-204**：支持当前 Windows 环境；会话与输入协议必须独立于首个客户端技术选择。

## 5. 生命周期与不变量

```text
CREATED -> RUNNING   start / 配置、种子与人类账户通过校验
RUNNING -> PAUSED    pause / 当前事务提交完成后停止推进
PAUSED  -> RUNNING   resume 或 step / step 只提交一个调度单位后再暂停
RUNNING -> COMPLETED end 或经济终点 / 写完整 trailer 与 manifest
*       -> ABORTED   不可恢复故障 / 丢弃失败事务并写稳定 abort code
```

不变量：

- `COMPLETED` 与 `ABORTED` 是终态，后续输入只能被拒绝，不能恢复会话。
- `input_seq` 严格递增；`assigned_timestamp` 单调不减；同一事务边界可共享时间戳，但复合键
  `(assigned_timestamp, input_seq)` 必须严格递增；每条输入恰有一个接受或拒绝结果。
- 人类市场动作与代理动作共用同一订单、风控、撮合和账本生产路径。
- 逻辑时间与事件全序规则不变；墙钟只在内核外节流。
- 交互运行及其派生产物永不进入正式研究证据。
- 输入重放只承诺同代码版本的逐事件一致；跨版本迁移须显式版本化，不静默改写。

## 6. 成功与验收

### 成功标准

- **SC-201**：固定演示配置下，用户在本地完成观察、合法下单、拒单、撤单、账户审查与
  正常结束的闭环。
- **SC-202**：至少一份 H1 成果包在新进程重放时，输入哈希、事件摘要和逐帧状态一致。
- **SC-203**：正式研究、统计、报告和 evidence index 入口对交互/未知模式产物的拒绝矩阵
  全部通过，且无部分写入。
- **SC-204**：成果包离线可打开，README 两次点击内能到达运行说明与代表性回放。

### 退出条件

| 退出 | 条件 | 证据 |
|---|---|---|
| E1 | 会话状态机、观察边界与控制接口通过正反测试 | session/controller tests |
| E2 | 本地客户端完成观察、下单、拒单、撤单和账户反馈闭环 | integration + real-environment evidence |
| E3 | 规范输入序列在新进程重放得到相同事件摘要与逐帧状态 | cross-process replay test |
| E4 | 所有正式证据入口 fail-closed 拒绝交互与未知模式，且不写部分产物 | evidence isolation matrix |
| E5 | 单命令生成完整 H1-C 成果包，离线打开并通过统一质量门 | bundle manifest + verify evidence |

### 验收清单

- [ ] **AC-001** (`FR-201`, `IR-201`, `IR-202`, `NFR-202`): 合法配置启动唯一交互会话；
      非法配置或重复启动原子拒绝。
- [ ] **AC-002** (`FR-202`, `IR-201`, `UX-201`, `NFR-204`): 观察快照只含当前已公开市场数据
      与本人状态；未完成 K 线、超过 k=10 tick 的深度、未来事件和代理私有状态不可见。
- [ ] **AC-003** (`FR-203`, `IR-201`, `TR-202`, `UX-202`): 人类下单/撤单走现有生产路径；
      合法动作提交，非法与风险不足动作无副作用拒绝。
- [ ] **AC-004** (`FR-204`, `IR-202`): 开始、暂停、继续、单步、结束遵守状态机；暂停不推进
      逻辑时间，同边界多输入共享时间戳且复合排序键严格递增。
- [ ] **AC-005** (`FR-205`, `TR-201`, `TR-202`, `IR-203`, `NFR-201`): 同代码、配置、种子
      与输入序列在新进程得到相同输入哈希、事件摘要和逐帧状态。
- [ ] **AC-006** (`FR-206`, `NFR-203`): 正式研究与证据入口分别拒绝任一侧为 interactive、
      manifest 模式缺失/未知、manifest/header 不一致；匹配的非 interactive 产物放行；批量
      扫描中任一候选违规则整批拒绝，evidence index 零部分写入。
- [ ] **AC-007** (`FR-207`, `IR-201`, `UX-201`, `UX-202`, `UX-203`, `NFR-204`): 本地客户端
      覆盖市场、账户、订单、输入结果及 design §6 映射的全部 UI 状态，并持续显示合成市场
      边界。
- [ ] **AC-008** (`FR-208`, `TR-203`, `IR-203`, `NFR-202`): 单命令生成完整、同源、可离线
      打开的 H1-C 成果包。

## 7. 测试、依赖与决策

### 测试策略

- 单元测试：会话状态机、输入规范化、逻辑时间分配、稳定错误码和 manifest 校验。
- 集成测试：真实订单/风控/撮合/账本路径、故障原子性、证据入口拒绝矩阵。
- 跨进程测试：同输入重放一致，以及篡改、截断、缺模式反例。
- 客户端测试：主要视图状态、下单/撤单反馈与断开恢复。
- 真实环境验证：Windows 本机完成 H1 用户旅程并断网打开成果包。

### 依赖

- 上游里程碑：0.1.5 `done / established`。
- 上游合同：事件 Schema、撮合、账户与保证金、代理策略、退化状态。
- 下游消费者：H2 人在环正式实验规格、后续教学与多用户体验。
- 外部依赖：首个客户端技术方案待 Q-201 决定；核心协议不得依赖该选择。

### 决策与风险

| 决策 / 风险 | 结论或缓解 | 理由 | 后续 |
|---|---|---|---|
| 交互结果被误作研究证据 | `run_mode=interactive` + 各正式入口 fail closed | 人类自由选择、学习与疲劳破坏预注册设计 | H2 独立协议 |
| 墙钟破坏确定性 | 记录分配后的逻辑时间；重放不读取墙钟 | UI 时序不可跨运行复现 | 冻结输入合同后实现 |
| UI 绕过核心规则 | 单一交互适配器调用现有生产入口 | 双业务路径会产生规则漂移 | 集成测试锁定 |
| 客户端技术锁死核心 | 会话/输入协议与 UI 分离 | H1 之后可能替换交互形态 | Q-201 只选择首个客户端 |
