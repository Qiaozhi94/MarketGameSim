# ADR-004：可视化采用事件日志回放，而非在线实时渲染

日期：2026-07-29  
状态：Accepted  
关联规格：[`../../specs/001-market-simulation-foundation/spec.md`](../../specs/001-market-simulation-foundation/spec.md)  
解决问题：PRD Q-005

## 背景

产品需要一个页面，随时间推移呈现价格走势与市场上交易者状态的变化，并在模拟结束后
输出总结报告。

约束：

- **NFR-004** 要求核心领域层不依赖 UI；
- **NFR-001 / KPI-002** 要求逐事件确定性与可复现；
- **KPI-004** 规定了基准仿真的性能门槛；
- **PR-013 / FR-008** 已要求记录订单、撤单、成交、订单簿快照、代理决策与账户快照。

## 决策

**可视化实现为事件日志的消费者，通过回放呈现，而非在仿真过程中在线渲染。**

- 仿真内核只写结构化事件日志（JSONL / Parquet），不感知任何呈现层；
- **M2 末尾交付单文件 HTML 回放器**：事件日志嵌入其中，纯前端逐帧播放，无需服务器，
  可直接存档进 `docs/experiments/`；
- **回放视图与总结报告是同一份 HTML 产物的两个视图**，共享同一数据源，保证指标口径
  一致；
- 同时输出一份 **Markdown 摘要**，用于 git 版本追溯与实验间 diff。

## 理由

离散事件仿真中"实时"不具备物理意义：基准仿真在数秒内即可跑完全部事件。要实现
在线实时呈现只有两条路径，均不可接受：

1. **为内核人为加入延迟以匹配人眼速度**——污染 KPI-004 的性能基准，并将 UI 时序
   耦合进内核，直接违反 NFR-004；
2. **跑完后按事件日志回放**——即本决策。

回放方案在各维度上均优于在线实时：

- **零内核侵入**：事件日志本就是 PR-013 的强制产物，回放器只是其消费者，NFR-004
  天然满足；
- **天然可复现**：同一份日志的回放结果恒定，与宪章第 3 条同构；在线实时渲染反而
  引入不可复现的渲染时序；
- **体验更优**：支持拖拽进度、倒退、变速、暂停查看盘口。调试关注的通常是"崩盘前
  200 个事件发生了什么"，实时流无法回看，回放可以；
- **不占用关键路径**：回放器为纯读取组件，可在 M2 之后独立开发，其失败不影响内核
  正确性。

## 备选方案

- **方案 A：在线实时页面（WebSocket / 轮询）**  
  优点：仿真进行中即可观察。  
  缺点：见上——需人为减速或耦合 UI 时序，违反 NFR-004 并污染性能 KPI；不可复现；
  无法回看。

- **方案 B：事件日志回放（已采纳）**  
  优点：见"理由"。  
  缺点：无法在长时间仿真进行中途观察进度（可由内核输出结构化进度日志缓解，该日志
  同样是日志消费者模式，不改变本决策）。

## 后果

- **正面**：核心层保持无 UI 依赖；可视化产物可存档、可分享、可作为实验证据；回放与
  报告共享数据源，避免两套指标口径不一致。
- **负面**：无法在仿真运行过程中实时观察；需要确保事件日志包含足够的周期性状态
  快照以支撑回放。
- **后续行动**：
  - **FR-008 的账户快照频率必须可配置**——否则回放中无法绘制持仓与 PnL 的演化曲线；
  - **PR-015 的分代理 / 分类型指标须按时间序列输出**，而不仅是终值，以支撑"市场上
    交易者的变化"这一呈现需求；
  - 在 PRD 功能范围中新增可视化与报告相关需求编号；
  - 回放器排入 M2 末尾交付。
