# ADR-001：时间推进采用离散事件内核

日期：2026-07-29  
状态：Accepted  
关联规格：[`../../specs/002-belief-testing-laboratory/spec.md`](../../specs/002-belief-testing-laboratory/spec.md)  
解决问题：PRD Q-002；任务 T005

## 背景

仿真需要决定时间如何推进：固定步长（每步推进固定时长，步内所有代理决策）还是
离散事件（事件按时间戳入优先队列，逐个弹出处理）。

约束来自已有需求：

- **FR-007** 要求"观察频率"和"通信延迟"作为显式可配置的代理能力；
- **A-003** 要求任何大资金优势可分解为资金、信息、**速度**或执行能力；
- **NFR-001** 要求相同代码、配置和种子产生逐事件一致的结果；
- **KPI-002** 要求重复运行产生相同的事件摘要哈希。

该决策阻塞 001 规格的 Phase 1 与 Phase 2 实现，必须在 M1 之前确定。

## 决策

采用**离散事件内核**：全局事件优先队列按时间戳弹出事件，代理的观察、决策、下单、
撤单、撮合和账户更新均建模为事件。不使用固定步长。

实现必须满足以下三条硬约束：

1. **整数逻辑时间戳（纳秒计），禁止浮点时间。** 浮点累加的舍入误差会破坏 NFR-001
   的逐事件一致性，并使 KPI-002 的哈希在不同平台上漂移。
2. **事件全序主键为 `(timestamp, priority_class, seq)`**，其中 `seq` 为全局单调递增
   计数器。订单簿的"时间优先"以订单到达的 `seq` 判定，而非 timestamp——同一时间戳
   到达的订单必须有确定顺序。任何定序不得依赖字典、集合的遍历顺序或对象标识。
3. **每个代理持有独立 RNG 流**，由 `SeedSequence(master_seed)` 按 `agent_id` 派生，
   禁止使用单一全局 RNG。

第 3 条是配对实验能否成立的前提：若使用全局 RNG，实验组比对照组多一个代理就会
使后续所有代理的随机流错位，观察到的差异中将混入随机流偏移，宪章第 3 条要求的
"相同外生路径和配对随机种子"随之失效。

## 备选方案

- **方案 A：固定步长（tick-based）**  
  优点：实现直观，步进循环易于理解。  
  缺点：**延迟只能量化为步长的整数倍**，要研究 5ms 与 50ms 的速度差异就必须把步长
  压到 1ms，此时已等价于事件队列但多出大量空转步；同时，步内多代理下单仍需一个
  步内全序规则来满足价格时间优先，等于换名重建事件队列，且更容易写出对遍历顺序的
  隐式依赖。该方案会使"速度"这一研究维度失去分辨率，与 A-003 和 M3 的研究目标冲突。

- **方案 B：离散事件（已采纳）**  
  优点：延迟、异质观察频率、订单到达时间均为一等公民；事件日志与内核时间模型天然
  同构，利于 FR-008 记录与回放；性能上只处理真实发生的事件。  
  缺点：需要显式设计全序与优先级类别，实现复杂度略高；调试时需要事件级追踪工具。

## 后果

- **正面**：速度优势可作为连续参数研究，直接支撑 A-003 与 M3 的能力归因；事件日志
  即内核状态转移序列，FR-008 的记录与确定性回放几乎零额外成本；RNG 分流使配对
  实验在代理构成变化时依然有效。
- **负面**：需要为事件定义优先级类别并维护其语义稳定性——优先级语义一旦变更，
  历史实验的事件哈希将不可比，须按宪章治理条款记录并评估影响。
- **后续行动**：
  - T005 标记为由本 ADR 解决；
  - 在指标字典中定义"事件"与"代理动作"的精确边界（见 ADR 关联的 KPI-004 口径问题）；
  - Phase 1 实现前先冻结事件优先级类别清单。
