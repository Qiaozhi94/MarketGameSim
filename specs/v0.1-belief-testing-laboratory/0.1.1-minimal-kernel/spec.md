## 1. 目标与非目标

**目标**：建成一个**没有杠杆**的确定性市场内核——订单簿、账户、事件日志、确定性
回放全部跑通，且守恒与因果链在整数域精确成立。

**为什么先做无杠杆**：账户结构一次留好保证金字段（`reserved_units`、
`entry_notional_units`），但本阶段不开启杠杆。理由是把两类缺陷分开——带着杠杆调
账本，会让「撮合/记账错误」与「保证金/强平错误」混在一起，定位成本成倍上升。
接口一次设计对，实现分两步，这不等于「后期叠加」。

**本阶段不做**：

- 保证金准入检查、强平、穿仓核销（0.1.2）；
- 信念因子、代理策略、做市商（0.1.2）；
- 资金费（第一版恒为 0，机制预留）；
- 批量实验与统计（0.1.2）；回放器与报告（0.1.4）。

**代理的替代**：0.1.1 用**脚本化订单流**（固定的订单序列，来自验收向量与撮合用例）
驱动内核，不实现任何代理。这使内核可以在没有 L2 的情况下独立验收。

## 5. 验收方式

```text
pytest tests/                      # 全部通过
python -m market_game_sim.verify --log <run.jsonl>
    → 重建账户终态、校验因果链、校验 C1/C2、输出事件摘要哈希
```

`verify` 是**独立于内核的检查器**：它只读事件日志，不导入 `kernel/` 或 `ledger/`。
若它复用内核代码，就无法证明日志自包含（SC-006 的意义所在）。
