## 0. 本里程碑为什么存在

FR-019、FR-020、SC-008、PR-018—PR-020、KPI-012 是 **v0.1 的必选需求**，但此前
0.1.1 把它们标为「0.1.2」、0.1.2 标为「0.1.3 或按需」、0.1.3 又标为「后续展示阶段」
——三个里程碑可以全部签收，而完整 v0.1 仍未交付这些能力。

本里程碑是对该缺口的**唯一修复**：给它们一个明确的所有者。**不能用「按需」表示
必选需求的归属**（封板审计 P0-O03）。

## 1. 目标

**把事件日志变成人能看懂的东西，且不引入第二个真源。**

回放器是事件日志的**消费者**，与内核完全解耦（v0.1 / D-7、ADR-004）。它证明的
不只是「好看」，而是一件有研究价值的事：**日志确实自包含**——若回放能仅凭日志还原
整段仿真，那么日志就足以支撑任何后续分析，不必保留内核。

## 2. 范围

| 项 | 内容 |
|---|---|
| **单文件 HTML 回放器** | 以事件日志为唯一输入，逐帧呈现价格、订单簿、账户与强平 |
| **K 线视图** | 周期定义见指标字典 §1.9，仅使用**已完成**的 K 线 |
| **总结报告** | 一次运行的指标汇总、PnL 桥接、经济终点与技术无效统计 |
| **逐帧一致性验收** | SC-008 / KPI-012：回放状态与原运行逐帧相等 |

**不在范围**：在线实时渲染（ADR-004 已排除——离散事件仿真中「实时」无物理意义）、
人在环交互、多运行对比看板（后者属 v0.2+）。

## 3. 硬约束

### 3.1 单文件、无服务端、无外部请求

产物为**一个 `.html` 文件**，双击即可打开：

- 数据以内联方式嵌入（JSON 或 base64），**不得**在运行时 `fetch` 任何资源；
- **不得**引用 CDN 上的脚本、样式或字体；
- 不依赖任何本地服务进程。

理由：回放产物要能随实验证据一起归档（NAS）并在数年后打开。任何外部依赖都会在
某个时点失效，而那时原始日志可能已经是唯一留存物。

### 3.2 回放器不得导入内核

与 `verify`（0.1.1 T603）同一理由：复用内核代码就无法证明日志自包含。回放器与
内核之间**只有日志文件**这一条通路。

### 3.3 大日志的降采样必须显式声明

研究运行的日志可能很大。允许降采样，但：

- 降采样比例与规则写入产物，**在页面上可见**；
- 逐帧一致性验收（E1）**必须在未降采样的日志上执行**——降采样后的一致性不构成
  SC-008 的证据。

## 4. 退出条件

| # | 条件 | 判据来源 |
|---|---|---|
| E1 | **逐帧一致性**：回放器仅以日志为输入，重建的价格、订单簿、账户状态与原运行**逐帧逐字段相等** | SC-008 / KPI-012 |
| E2 | 产物为单文件 HTML，**离线打开可用**，无任何外部请求 | §3.1；用断网环境验收 |
| E3 | K 线视图与指标字典 §1.9 的周期定义一致，且只用已完成 K 线 | FR-020 |
| E4 | 总结报告覆盖 PR-018—PR-020 声明的内容，数值与 `metrics/` 的输出**同源** | PR-018—PR-020 |
| E5 | 回放器与报告**不导入** `kernel/`、`ledger/`、`book/` | §3.2；导入检查测试 |

## 6. 已知风险

| 风险 | 应对 |
|---|---|
| 回放器悄悄重新实现撮合逻辑，形成第二个真源 | E5 的导入检查只挡代码复用，挡不住重新实现；**E1 的逐帧一致性才是真正的防线**——重新实现且不一致会立刻失败 |

| 报告数值与 `metrics/` 输出不一致 | E4 要求同源：报告读 `metrics/` 的产物，不自行重算 |
