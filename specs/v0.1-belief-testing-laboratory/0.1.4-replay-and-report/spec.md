## 0. 本里程碑为什么存在

FR-019、FR-020、SC-008、PR-018—PR-020、KPI-012 是 **v0.1 的必选需求**，但此前
0.1.1 把它们标为「0.1.2」、0.1.2 标为「0.1.3 或按需」、0.1.3 又标为「后续展示阶段」
——三个里程碑可以全部签收，而完整 v0.1 仍未交付这些能力。

本里程碑是对该缺口的**唯一修复**：给它们一个明确的所有者。**不能用「按需」表示
必选需求的归属**（封板审计 P0-O03）。

## 1. 目标

**把事件日志变成人能看懂的东西，且不引入第二个真源。**

回放器是事件日志的**消费者**，与内核完全解耦（v0.1 / D-7）。它证明的
不只是「好看」，而是一件有研究价值的事：**日志确实自包含**——若回放能仅凭日志还原
整段仿真，那么日志就足以支撑任何后续分析，不必保留内核。

## 2. 范围

| 项 | 内容 |
|---|---|
| **单文件 HTML 回放器** | 以事件日志为唯一输入，逐帧呈现价格、订单簿、账户与强平 |
| **K 线视图** | 周期定义见指标字典 §1.9，仅使用**已完成**的 K 线 |
| **总结报告** | 一次运行的指标汇总、PnL 桥接、经济终点与技术无效统计 |
| **逐帧一致性验收** | SC-008 / KPI-012：回放状态与原运行逐帧相等 |

**不在范围**：在线实时渲染（**v0.1 / D-7 已排除**——离散事件仿真中「实时」无物理意义）、
人在环交互、多运行对比看板（后者属 v0.2+）。

## 3. 硬约束

### 3.1 单文件、无服务端、无外部请求

产物为**一个 `.html` 文件**，双击即可打开：

- 数据以内联方式嵌入（JSON 或 base64），**不得**在运行时 `fetch` 任何资源；
- **不得**引用 CDN 上的脚本、样式或字体；
- 不依赖任何本地服务进程。

理由：回放产物要能随实验证据一起归档（NAS）并在数年后打开。任何外部依赖都会在
某个时点失效，而那时原始日志可能已经是唯一留存物。

### 3.2 回放器不得导入内核

与 `verify`（0.1.1 T603）同一理由：复用内核代码就无法证明日志自包含。回放器与
内核之间**只有日志文件**这一条通路。

### 3.3 大日志的降采样必须显式声明

研究运行的日志可能很大。允许降采样，但：

- 降采样比例与规则写入产物，**在页面上可见**；
- 逐帧一致性验收（E1）**必须在未降采样的日志上执行**——降采样后的一致性不构成
  SC-008 的证据。

| E4 | **总结报告**含条件性结论、效应量、置信区间与失效边界，且全部数值消费 §4.1 的上游 artifact，**不自行重算** | **PR-019** |
| E5 | 回放器与报告**不导入** `kernel/`、`ledger/`、`book/` | §3.2；导入检查测试 |

### 4.1 报告的上游 artifact 合同

E4 的「同源」不等于「一切都来自 `metrics/`」——**效应量、置信区间与失效边界是分析
结果，不是指标**，它们由 0.1.2/0.1.3 的实验编排层产出。

报告的输入是一份 **artifact manifest**，列出被消费的冻结产物及其哈希：

| 产物 | 来源 | 内容 |
|---|---|---|
| `metrics/*` | 0.1.2 T501—T503 | 市场与代理指标时间序列、PnL 桥接 |
| `analysis/*` | 0.1.2 T604 | 效应量、置信区间、多重比较校正结果 |
| `conclusion/*` | 0.1.2 T605、0.1.3 T6xx | 条件性结论、失效边界、否定条件 |

**规则是「不重算」，不是「只读 metrics」**：报告层不得自己跑统计检验或重新聚合，
但可以且必须消费上述三类产物。若把数值来源限定在 `metrics/`，E4 会在漏掉 PR-019
核心内容（条件性结论与置信区间）的情况下自称通过。

manifest 须冻结：`manifest_version`、每个 artifact 的**相对路径、producer task、
blake2b 哈希**、以及**缺件行为**（任一必备 artifact 缺失或哈希不符 → 报告生成失败，
不得降级为「部分报告」）。

### 4.2 逐帧一致性的 oracle 从哪来

E1 断言「回放重建的每一帧 == 原运行的每一帧」，**右边那个「原运行」不能取自事件
日志本身**——那样就是拿日志验证日志，循环自证，回放器即使把撮合重实现错了也能通过。

因此 oracle 由**测试专用的独立 observer** 提供：

- 测试运行时挂载一个 observer，在**每个事务提交后**直接从内核对象读取状态快照；
- 投影字段与回放器输出**一一对应**（价格、盘口聚合、各账户的 9+2 个字段）；
- **该 observer 只作为期望值输入，绝不喂给回放器**——回放器的输入永远只有日志文件；
- observer 属测试代码，不进入 `kernel/`，也不影响生产路径的确定性。

一句话：**回放器读日志，oracle 读内核，两条独立路径的结果必须相等。**

## 6. 已知风险

| 风险 | 应对 |
|---|---|
| 回放器悄悄重新实现撮合逻辑，形成第二个真源 | E5 的导入检查只挡代码复用，挡不住重新实现；**E1 的逐帧一致性才是真正的防线**——重新实现且不一致会立刻失败 |
| 单文件内联大日志导致产物过大、浏览器卡死 | §3.3 允许降采样，但一致性验收在完整日志上做 |
| 报告数值与上游产物不一致 | E4 要求消费 §4.1 的三类冻结 artifact（`metrics/`+`analysis/`+`conclusion/`）并核对哈希，报告层不自行重算 |
| 逐帧 oracle 取自日志自身，形成循环自证 | E1 的期望值**必须由测试专用的独立 observer 提供**，见 §4.2 |
