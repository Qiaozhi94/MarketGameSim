# Implementation Plan: Market Simulation Foundation

**对应规格**：`specs/001-market-simulation-foundation/spec.md`  
**状态**：**Approved**（T000i，2026-07-31）

## 技术上下文

- Python 3.11+
- `src` 布局，核心领域层仅使用标准库（ADR-002 / KR-005）
- pytest + 属性/不变量测试
- 输出 JSONL/Parquet；可视化为事件日志的消费者，不进入核心层（ADR-004）
- 离散事件内核，整数逻辑时间戳，事件全序 `(timestamp, priority_class, seq)`，
  每代理独立 RNG 流（ADR-001 / KR-001—KR-004）

## 组件边界

```text
EventQueue（离散事件，整数时间戳）
        ↓
Agent → OrderGateway → Exchange/OrderBook → Trade
  ↑                ↓            ↓            ↓
ObservationBus  Risk/Ledger  ConstraintHooks  EventLog
                                                 ↓
                                    Replayer / Report（独立进程，只读）
```

`ConstraintHooks` 为交易所层的约束插槽（订单准入校验、可交易数量计算、价格边界）。
MVP 的加密现货配置下这些钩子基本为空实现，但接口须从 Phase 1 起存在，使 T+1、
涨跌停等制度将来能以插件接入而非重写撮合核心（PRD §10.2）。

`Replayer / Report` 只消费 `EventLog`，不被核心层引用（NFR-004）。

## 阶段

1. 领域模型与确定性撮合（含约束钩子接口）。
2. 离散事件内核、账户、风控和事件日志。
3. 基准代理集合（噪声、趋势、均值回复、库存型做市商）与内生锚。
4. 回放器与报告；批量实验、统计指标和验证。
5. M3 引入能力异质性代理（羊群、大资金执行者、订单流预知者）。

ABIDES/PAMS 的兼容或迁移不再作为默认计划项——按 ADR-002，仅在 M4 出现具体互操作
需求（如复用外部 RL 训练环境）时重新立项。

## 关键风险

- 代理规则可能预先决定实验结论：使用消融实验、参数扫描和盲化分析缓解；研究问题的
  提法须通过 methodology §11.1 的可证伪性判据。
- 内生锚的自指结构可能产生非预期动力学（锁定、周期振荡或发散）：Phase 4 参数扫描
  确认稳定区间，不稳定区间作为结果报告。
- 统计特征可能只在狭窄参数区间出现：保存失败区域，不做选择性报告。
- 允许极端行情导致有效样本减少：预先声明发散样本判定，报告排除率并据此调整样本量。
- 过早追求真实交易所细节：以验收指标作为范围边界。
