# Feature Specification: Market Simulation Foundation

**规格编号**：001-market-simulation-foundation  
**状态**：Draft  
**创建日期**：2026-07-28  
**更新日期**：2026-07-30  
**已生效决策**：[ADR-001](../../docs/adr/001-discrete-event-time-kernel.md)、[ADR-002](../../docs/adr/002-build-minimal-kernel.md)、[ADR-003](../../docs/adr/003-crypto-spot-market-without-fundamentals.md)、[ADR-004](../../docs/adr/004-replay-based-visualization.md)、[ADR-005](../../docs/adr/005-numeric-and-serialization-contract.md)、[ADR-006](../../docs/adr/006-same-timestamp-event-scheduling.md)

## 问题与目标

建立一个本地运行、订单簿驱动、可复现的**加密现货**实验环境，用于观察异质散户和
不同类型大资金代理的交互如何形成价格、流动性和财富分配。

模型中不存在外生基本价值过程，价格路径完全由订单流互动内生产生。

## 非目标

- 不预测真实证券或加密资产的未来价格。
- 不连接交易所、券商、钱包或真实资金。
- 不把做市、大资金执行和市场操纵合并为同一种“庄家”。
- 第一版不使用强化学习、LLM、社交媒体或多品种套利。
- 不实现永续合约与资金费率（现货 only）。
- 不锁定具体币种，不做真实数据校准。

## 用户场景与验收

### US-1：运行基准市场（P1）

作为研究者，我可以使用固定配置和随机种子运行单品种连续竞价仿真，并获得完全一致
的订单、成交和账户结果。

### US-2：比较参与者结构（P1）

作为研究者，我可以改变各类代理数量与能力，通过批量实验比较价格、流动性和 PnL。

### US-3：解释行为与结果（P2）

作为研究者，我可以从任一成交追溯到代理观察、决策规则、订单及账户状态变化。

## 功能需求

- **FR-001**：系统必须实现价格时间优先的单品种限价订单簿，按加密现货制度 24/7
  连续交易，无休市、无集合竞价、无涨跌停、无 T+1、无整手限制。
- **FR-002**：系统必须支持限价单、市价单、撤单及部分成交。
- **FR-003**：系统必须阻止超出可用现金或可用持仓的订单，并支持 tick size（含极细
  粒度）、最小数量及 **maker / taker 分离计费**的手续费配置。价格、数量与金额一律
  以最小单位整数承载，手续费为唯一舍入点且舍入方向固定；手续费须在下单时按上界
  预冻结（[ADR-005](../../docs/adr/005-numeric-and-serialization-contract.md)）。
- **FR-004**：系统必须维护现金、持仓、冻结量、费用和已实现/未实现 PnL。
- **FR-005**：系统必须提供噪声、趋势、均值回复和羊群型散户代理。均值回复代理锚定
  **内生**的指数加权移动均价（EWMA），各代理半衰期从以 τ 为中心、σ 为离散度的分布
  中抽取，不得共用同一值；系统中不得存在外生基本价值过程。
- **FR-006**：系统必须分别提供库存型做市商、大资金执行者和订单流预知者。订单流
  预知者的信息优势表现为提前 N 个事件获知大单到达，N 与可见范围为显式配置参数。
- **FR-007**：代理能力必须显式配置资金、信息（订单流可见范围与提前量）、观察频率
  和通信延迟。**通信延迟与观察到决策的间隔均不得为 0**（下界 1 ns，KR-006），零值
  配置在校验阶段拒绝。
- **FR-008**：系统必须记录订单、撤单、成交、订单簿快照、代理决策和账户快照，
  **账户快照频率必须可配置**。事件必须携带因果外键（`observation_event_id`、
  `decision_event_id`、`intent_id`、`caused_by_event_id`、`target_order_id`），使
  「成交 → 订单 → 意图 → 决策 → 观察」的追溯链在日志内自包含、可机器验证，不依赖
  重放（[ADR-006](../../docs/adr/006-same-timestamp-event-scheduling.md)）。
- **FR-009**：实验配置必须包含随机种子并可序列化。
- **FR-010**：系统必须支持同一场景的多种子批量运行和分组汇总。
- **FR-011**：各代理及代理类型的收益、回撤、库存和交易成本必须按**时间序列**输出，
  而不仅是终值。
- **FR-012**：系统必须为退化状态定义确定行为——价格下界、代理破产后行为、订单簿
  单边清空时的市价单处理、长时间无成交的判定。允许极端行情发生，但**领域层不得
  产出未定义状态或崩溃**。未定义的量（单边簿下的 `mid` 等）在输出层以缺失值
  （JSONL / Parquet 的 `null`）表达，NaN 仅是分析层读取后的统计表示，不写入日志
  （ADR-005 §6）。
- **FR-013**：系统必须提供单文件 HTML 回放器，以事件日志为唯一输入逐帧呈现价格、
  订单簿与代理状态演化，支持拖拽进度、变速与暂停；回放视图与总结报告为同一产物的
  两个视图，共享同一数据源。仿真内核不得依赖呈现层。

## 时间与随机性内核

- **KR-001**：时间推进采用离散事件内核，不使用固定步长。
- **KR-002**：时间戳必须为整数逻辑时间（纳秒计），禁止浮点时间。
- **KR-003**：事件全序主键为 `(timestamp, priority_class, seq)`，`seq` 为全局单调
  递增计数器。订单簿的时间优先以订单到达的 `seq` 判定。任何定序不得依赖字典、集合
  的遍历顺序或对象标识。
- **KR-004**：每个代理必须持有独立 RNG 流，由 `SeedSequence(master_seed)` 按
  `agent_id` 派生；禁止使用单一全局 RNG。
- **KR-005**：核心领域层仅使用 Python 标准库，不引入外部仿真框架作为依赖。
- **KR-006**：处理事件 `e` 期间产生的任何新事件 `e'` 必须满足 `key(e') > key(e)`，
  违反时立即终止运行，不得静默重排。推论：同一时间戳内只能沿 `priority_class`
  递增方向推进，要回到更小的 class 必须先推进 `timestamp`——因此禁止零通信延迟
  （FR-007）。若无此约束，`AGENT_DECIDE` 产生的 `ORDER_ARRIVAL` 会破坏事件队列
  单调性，使 KR-003 的全序语义与 KPI-002 的哈希输入顺序同时失效
  （[ADR-006](../../docs/adr/006-same-timestamp-event-scheduling.md)）。

## 研究与模型假设

- **A-001**：成交价格完全由订单交互形成。系统中不存在外生基本价值过程；均值回复力
  由锚定内生长周期价格统计量的代理提供。
- **A-002**：代理只能使用其信息集内的数据，不具有全知视角。
- **A-003**：任何大资金优势都能分解为资金、信息、速度或执行能力。在无基本面的模型
  中，"信息"维度由**对未来订单流的提前可见性**承载。
- **A-004**：内生锚含自指结构，其稳定性不得假定。锁定、发散与周期振荡三种失效形态
  必须通过 τ × 趋势代理占比的二维参数扫描识别，可用区间与失效区间均须作为结果报告
  （判据见 ADR-003 §2.3）。

## 非功能需求

- **NFR-001**：相同代码、配置和种子必须产生逐事件一致的结果。
- **NFR-002**：订单簿和账本核心逻辑应具有至少 90% 分支覆盖率。
- **NFR-003**：基准配置 `benchmarks/BENCH-001.yaml`（固定代理构成、固定事件数、固定
  种子）在指定参考硬件上的单核运行时间不超过 10 秒。
- **NFR-004**：核心领域层不得依赖 UI、数据库或机器学习框架。

## 成功指标

- **SC-001**：撮合、优先级、部分成交、撤单和资金持仓守恒测试全部通过。
- **SC-002**：固定种子的两次运行产生相同事件摘要哈希。
- **SC-003**：研究者能通过单个命令运行不少于 30 个种子的对照实验。
- **SC-004**：报告至少包含收益、波动率、点差、深度、成交量、价格冲击和各类代理 PnL。
- **SC-005**：基准市场验证报告明确给出通过、失败或不适用的统计特征，并报告发散样本
  的判定标准与排除率。
- **SC-006**：回放器仅以事件日志为输入即可还原整段仿真，回放结果与原运行逐帧一致。
- **SC-007**：指标字典 §5 的守恒等式在**整数域精确成立**（相等断言，非容差断言），
  且在不可整除的手续费、恰好位于冻结边界的订单、负 maker 费率返佣三类情形下均成立。
- **SC-008**：遍历事件日志中的**全部**成交，因果链每一跳的目标事件唯一存在且全序键
  严格更小；断链、悬空引用或多重匹配即判定运行不合格。该检查不依赖重放。

## 边界情况

以下场景必须有明确定义的行为（FR-012），不得产出未定义状态：

- 空订单簿上的市价单——须定义拒绝、挂单或部分执行中的一种。
- 价格相同但到达时间不同的订单——按 `seq` 定序（KR-003）。
- 部分成交后撤销剩余数量。
- 资金或持仓恰好位于约束边界。
- 代理破产——须定义退出还是保留但禁止新开仓。
- 价格趋近下界——须定义下界为 0 还是 1 tick，以及是否允许无上界发散。
- 订单簿单边被清空。
- 长时间无成交——须定义判定阈值与处理方式。
- 价格发散——须定义发散样本的判定标准与排除规则。
- 手续费不可整除至最小结算单位——按 ADR-005 §3 向不利于代理的方向取整，余数归于
  交易所累计费用。
- 同一时间戳内产生更高优先级事件——由 KR-006 禁止，配置校验阶段即排除零延迟。

- **Q-010**：内生锚半衰期离散度 σ 的初始取值范围，由 EXP-000 的 X-002 敏感性子实验
  在 M2 回写。

ADR-001 至 ADR-004 解决。**Q-009（参考硬件口径）已由

ADR-005、ADR-006 关闭。
