# MarketGameSim Constitution

版本：1.0.0  
批准日期：2026-07-28

## 1. 可追溯规格优先

任何功能必须先有已评审的规格。实现、测试、实验指标和结论必须引用需求编号；
未写入规格的行为不视为产品承诺。

## 2. 撮合正确性不可妥协

订单生命周期、价格时间优先、现金与持仓守恒、费用和交易约束必须通过确定性测试。
影响账本或价格形成的缺陷属于阻断性问题。

## 3. 实验必须可复现

每次实验必须保存配置、随机种子、代码版本、运行时间和指标定义。比较策略时使用相同
的外生路径和配对随机种子；单次运行不得作为一般性结论。

## 4. 区分角色、能力与行为

做市商、大资金执行者、知情交易者和操纵型代理必须建模为不同角色。资金、信息、
延迟和市场影响是显式能力，不得以“庄家能控制价格”等隐藏假设代替机制。

## 5. 先验证市场，再解释策略

在解释代理盈亏前，基准市场必须通过预先声明的统计和微观结构检查。模型结论应写成
“在这些假设与参数下”，不得直接外推为真实市场预测或投资建议。

## 6. 安全与合规边界

操纵行为只能用于封闭仿真、检测和监管压力测试。项目不得连接真实交易账户，不得将
实验输出包装为实施市场操纵的操作指南。

## 7. 小步、确定性、可观察

优先实现单品种、规则代理和最小订单类型。所有状态变化必须可记录、可回放、可解释；
强化学习、LLM、多市场等能力必须在基础模型验证后通过独立规格引入。

## 治理

- 违反宪章的规格不得进入实现阶段。
- 修改宪章必须说明原因、迁移影响并提升版本号。
- 每个功能评审都必须检查：规格完整性、测试证据、复现信息和研究边界。
